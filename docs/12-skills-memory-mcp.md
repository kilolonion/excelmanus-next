# 12 技能、记忆、规则与 MCP

## 1. 技能

### 1.1 定位【硬性】

技能教代理**怎么完成某一类工作**：步骤、判断要点、质量标准、常见陷阱。它不定义工具，也不重复工具的参数说明（分工见 [04 §7.1](04-agent-runtime.md#71-三层分工硬性)）。

例：`report-building`（报表制作）技能写"先确认口径与期间 → 用 SQL 汇总 → 新建汇总表而不是改原表 → 图表类型怎么选 → 数字格式与表头样式规范 → 交付前用 `check` 核对合计"。它会提到 `workbook_analyze`，但不解释其参数。

### 1.2 格式

与业界通行的 Agent Skills 目录格式兼容（一个目录 + `SKILL.md`，frontmatter 至少含 `name`、`description`），便于导入社区技能：

```markdown
---
name: report-building
description: 制作汇总报表与图表。用户要求"汇总""做报表""月报""画图"时使用。
requires-tools: [workbook_read, workbook_analyze, workbook_edit]
file-patterns: ["*.xlsx", "*.csv"]
user-invocable: true
model-invocable: true
version: 1.0.0
---

# 报表制作
……
```

| 字段 | 说明 |
| --- | --- |
| `name` | kebab-case，唯一 |
| `description` | 做什么 + 何时使用（进入系统提示词的技能索引，控制在 100 字内） |
| `requires-tools` | 依赖的工具；任一不可用则技能不出现 |
| `file-patterns` | 可选；工作区或当前消息涉及匹配文件时，技能在索引中排序靠前 |
| `user-invocable` | 用户能否用 `/<name>` 调用 |
| `model-invocable` | 模型能否自行加载 |
| 资源 | 目录下的其他文件（如 `references/*.md`），通过 `read skill://<name>/<路径>` 读取 |

### 1.3 来源与优先级

| 来源 | 位置 | 优先级 |
| --- | --- | --- |
| 内置 | 应用包内 `assets/skills/` | 低 |
| 用户 | `<数据目录>/skills/` | 中 |
| 工作区（P1） | `<工作区>/.excelmanus/skills/` | 高 |

同名时高优先级整体覆盖低优先级（不合并）。v1 不支持技能 hooks（旧版协议中的 hook 机制推迟到 P2）。

### 1.4 使用

- 系统提示词中的技能索引只列名称与描述。
- 模型用 `skill` 工具加载正文；用户用 `/<name>` 调用时，运行时直接把技能正文作为本轮上下文注入。
- 加载技能不改变权限、不增加工具。

### 1.5 导入【硬性：安全检查】

- 来源：本地目录、GitHub 仓库地址（仅 `github.com`，下载压缩包 ≤ 20 MB，条目 ≤ 2,000）。
- 拒绝符号链接、路径穿越、可执行文件以外的二进制大文件（单文件 > 5 MB）。
- 导入后显示技能正文供用户确认，默认启用。
- 导入的技能若引用不存在的工具，标记为"不可用"并说明缺少哪些工具。

### 1.6 v1 内置技能【推荐】

| 技能 | 用途 |
| --- | --- |
| `excelmanus-guide` | 产品自我说明：有哪些功能、设置在哪、限制是什么（替代旧版知识门户） |
| `report-building` | 汇总报表与图表 |
| `data-cleaning` | 去重、规范格式、拆分合并列、异常值标记 |
| `reconciliation` | 两份或多份数据的核对与差异报告 |
| `formula-help` | 公式编写、解释与排错 |
| `sheet-styling` | 表格美化规范（配色、字体、对齐、数字格式、打印） |
| `image-to-sheet` | 截图/票据转可编辑表格：识别 → 生成 → 截图对照 → 修正 |
| `batch-files` | 多文件批量处理，何时拆给子代理、如何分工与汇总 |
| `script-patterns` | `run_script` 的常用模式与性能要点 |

每个内置技能需有至少一个真实模型评测场景（[14 §6](14-quality.md#6-真实模型评测)）证明它确实改善了结果。

## 2. 记忆

### 2.1 内容

| 类别 | 示例 |
| --- | --- |
| `preference` 用户偏好 | "金额保留两位小数，用千分位" |
| `domain` 业务知识 | "本公司'收入'口径为含税" |
| `file` 文件说明 | "budget.xlsx 的'汇总'表由财务手工维护，不要改" |
| `lesson` 经验 | "分公司表的日期列经常混有文本日期" |

范围：全局，或限定某个工作区。

### 2.2 写入

- 代理用 `memory save` 保存；每次保存在对话中显示"已记住：……"并提供"撤销"。
- 用户可在设置中新增、编辑、删除。
- v1 不做会话结束后的自动记忆提取（会产生额外模型调用）；P2 可作为可选功能。

### 2.3 使用【推荐】

- 每轮开始时，按与用户消息和当前工作区的相关度（关键词匹配 + 最近使用）选出若干条，放入该轮用户消息前的 `<context>` 块（不进系统提示词，以免破坏缓存，见 [04 §7.3](04-agent-runtime.md#73-缓存友好的前缀规则硬性)），总量不超过约 1,500 token；本会话已注入过的记忆不重复注入。
- 代理可用 `memory search` 主动检索。
- 子代理默认只获得与任务相关的记忆，且只能 `search`（worker 以下角色不能 `save`/`delete`）。

## 3. 规则

- 全局规则与会话规则，用户在设置或 `/rules` 中管理，按启用状态原样注入系统提示词；会话中途修改规则时以追加说明告知代理（[04 §7.3](04-agent-runtime.md#73-缓存友好的前缀规则硬性)）。
- 单条规则 ≤ 2,000 字，全部规则总量 ≤ 8,000 字，超出时设置页提示。
- 工作区说明文件（P1）：工作区根目录下的 `EXCELMANUS.md` 若存在，作为该工作区的规则自动注入（类似代码仓库中的 AGENTS.md），界面显示已加载。

## 4. MCP

### 4.1 支持范围

| 项 | v1 |
| --- | --- |
| 传输 | stdio（本机与桌面）、Streamable HTTP；旧式 SSE 传输兼容（若所选客户端库支持） |
| 能力 | 工具（tools）。资源（resources）与提示词（prompts）为 P2 |
| 配置 | 名称、命令与参数与环境变量，或 URL 与请求头；敏感值加密存储 |

### 4.2 行为

- 工具以 `mcp__<服务器>__<工具>` 命名加入工具列表（名称超长时截断并附短哈希，保证唯一且 ≤ 64 字符）。
- `readOnlyHint=true` 的工具视为只读；其他视为 `external`，按权限模式审批，可在设置中为单个工具加入自动批准名单。
- 连接：应用启动时后台连接已启用的服务器；失败按指数退避重连；状态（已连接/连接中/失败及原因）在设置页显示。
- 服务器的工具列表变化时，运行时在下一个步骤边界刷新工具列表。
- 超时：连接 15 秒，单次调用默认 60 秒（可按服务器配置）。
- 结果按 [06 §2.3](06-tools.md#23-统一结果结构硬性) 截断；返回的图片在模型支持视觉时作为视觉输入。
- stdio 服务器需要宿主机上有对应命令（如 `npx`、`uvx`）；桌面版不捆绑这些命令，界面在命令不存在时给出明确提示。
- 默认不预装任何 MCP 服务器（隐私）；设置页可提供常用服务器的配置模板（P1）。
