## 架构一句话

**会话日志是会话状态的唯一事实源**（一切状态变化先写日志，投影可重建）；**工作簿是被用户与代理实时共同编辑的活文档**（文档 actor 持有内存模型，操作按修订号串行应用，xlsx 是异步检查点）；有状态对象都是 **actor**；能力以**模块**接入；所有客户端通过 **REST + 同步通道**（WebSocket）访问同一后端。详见 [03 系统架构](03-architecture.md)。

## 约束等级

文档中的要求按三级标注，实现者据此判断可以改动的范围：

| 标记 | 含义 | 可否偏离 |
| --- | --- | --- |
| **【硬性】** | 产品承诺、安全边界、数据正确性、用户已拍板的决策 | 不可偏离；如确需调整，先改文档并由产品负责人确认 |
| **【推荐】** | 经过评估的默认方案，附理由与备选 | 可以换，但要在 `docs/decisions/` 写一份决策记录（ADR），说明新方案如何满足同一组验收标准 |
| **【开放】** | 只给目标和验收标准，不规定做法 | 实现者自行设计 |

没有标记的描述性文字视为【推荐】。

**文档规定"做什么"和"做到什么程度"，尽量不规定"怎么写代码"。** 目录结构、类名、函数签名在文档中只作示意，除非标了【硬性】。

## 已确定的产品决策（2026-09-28）

以下决策由产品负责人确认，属于【硬性】：

1. 新项目目录 `~/Desktop/excelmanus-next`，与旧仓库完全独立。
2. v1 形态：**本机 Web + 后端**、**桌面 App（Windows/macOS）**。服务器部署、Android、远程中继进入后续阶段，v1 只预留接口。
3. **TypeScript 全栈**。不引入 Python 运行时（包括代码沙箱）。
4. Agent 内核与多提供商适配**选用成熟开源组件**，不自己写提供商协议适配。
5. v1 保留：订阅账号登录（ChatGPT/Codex）、记忆与规则、后台子代理、运行中消息的三种派发策略。
6. **移除 Word 能力**。
7. **移除文件历史恢复承诺**（修订历史、撤销、恢复到旧版本），改为轻量的"修改前备份"机制。
8. 子代理改为**可互相通信的协作模型**，不再是一次性派发后阻塞等待。
9. 重新设计工具集：合并、精简，通用文件操作不再逐个做成工具。
10. 严格区分**技能**（教代理某类工作流）与**工具说明**（教代理某个工具的用途与边界）。
11. 前端围绕"表格代理"深度设计：选区联动、区域高亮、带选区的提问确认等。
12. 预留手机端方案，支持手机连接电脑。
13. **不迁移任何旧数据**，新版全新开始。
