## 架构一句话

**会话日志是会话状态的唯一事实源**（一切状态变化先写日志，投影可重建）；**工作簿是被用户与代理实时共同编辑的活文档**（文档 actor 持有内存模型，操作按修订号串行应用，xlsx 是异步检查点）；有状态对象都是 **actor**；能力以**模块**接入；所有客户端通过 **REST + 同步通道**（WebSocket）访问同一后端。详见 [03 系统架构](03-architecture.md)。

## 约束等级

文档中的要求按三级标注：

| 标记 | 含义 | 怎么改 |
| --- | --- | --- |
| **【硬性】** | 核心架构与数据正确性约定（会话日志、活文档、不破坏用户文件等），以及已拍板的产品决策 | 改之前想清楚影响，改完同步文档；影响全局的取舍写一份简短 ADR |
| **【推荐】** | 默认方案 | 可以直接换，在提交说明里写一句原因即可 |
| **【开放】** | 只给目标 | 自行设计 |

没有标记的描述性文字视为【推荐】。

**2026-10-11 轻量化**：测试、验收、门禁、证据类要求一律以 [14 质量](14-quality.md) 为准，其他章节中残留的"必须有测试 / 证据 / 门禁 / 验收"字样不再作为要求。安全相关章节描述的是已经实现的防护，保持现状即可，不再追加新的加固要求。

**文档规定"做什么"和"做到什么程度"，尽量不规定"怎么写代码"。** 目录结构、类名、函数签名在文档中只作示意，除非标了【硬性】。

## 已确定的产品决策（2026-09-28）

以下决策由产品负责人确认，属于【硬性】：

1. 新项目目录 `~/Desktop/excelmanus-next`，与旧仓库完全独立。
2. v1 形态：**本机 Web + 后端**、**桌面 App（Windows/macOS）**。服务器部署、Android、远程中继进入后续阶段，v1 只预留接口。
3. **TypeScript 全栈**。不引入 Python 运行时（包括代码沙箱）。
4. Agent 内核与多提供商适配**选用成熟开源组件**，不自己写提供商协议适配。
5. v1 保留：订阅账号登录（ChatGPT/Codex）、记忆与规则、后台子代理、运行中消息的三种派发策略。
6. **移除 Word 能力**。
7. **移除文件历史恢复承诺**（修订历史、撤销、恢复到旧版本），改为轻量的"修改前备份"机制。
8. 子代理改为**可互相通信的协作模型**，不再是一次性派发后阻塞等待。
9. 重新设计工具集：合并、精简，通用文件操作不再逐个做成工具。
10. 严格区分**技能**（教代理某类工作流）与**工具说明**（教代理某个工具的用途与边界）。
11. 前端围绕"表格代理"深度设计：选区联动、区域高亮、带选区的提问确认等。
12. 预留手机端方案，支持手机连接电脑。
13. **不迁移任何旧数据**，新版全新开始。
14. **定位为小型开源项目，功能优先**（2026-10-11）：不追求全面测试、发布认证和过度防御，开发约定见 [AGENTS.md](../AGENTS.md)。

## 维护规则

- 文档与实现冲突时改成一致：哪边对就改另一边。
- 待办、缺口和已知问题只记在 [backlog](backlog.md)，不在多个文档里重复维护进度。
- 不要求里程碑验收记录；`acceptance/` 是历史存档，不再新增。只有影响全局的取舍（换核心依赖、改【硬性】约定）才写 ADR：`docs/decisions/NNNN-标题.md`，用几段话说清背景、决定和后果。
- 技能与帮助内容的分工见 [17](17-skill-authoring.md)；用户帮助源文件为 [user-guide.md](user-guide.md)，技能评测见 [skill-evals.md](skill-evals.md)。
