# 09 模型与提供商

## 1. 原则

- 提供商协议适配**用成熟库**（Vercel AI SDK 7 及其官方 provider 包），不自己实现协议【硬性】。
- 所有提供商相关代码集中在 `models` 包的模型网关后面（[03 §5.2](03-architecture.md#52-决定推荐)），运行时与数据库只见中立格式。
- 能力以**证据**为准：官方元数据、实测探测、用户手动覆盖三类来源分开记录；未知就是未知，不假定支持。

## 2. 提供商映射【推荐】

| 提供商 | 适配包 | 说明 |

| OpenAI | `@ai-sdk/openai` | 默认 Responses API；可选 Chat Completions |
| Anthropic | `@ai-sdk/anthropic` | 支持提示词缓存（`cacheControl`） |
| Google Gemini | `@ai-sdk/google` | |
| DeepSeek | `@ai-sdk/deepseek` | 官方包处理 `reasoning_content` 回传 |
| Kimi（Moonshot） | `@ai-sdk/moonshotai` | |
| 通义千问、智谱、豆包、MiniMax、小米 MiMo 等国产服务 | `@ai-sdk/openai-compatible` | 按提供商配置兼容参数；若有维护良好的社区包且支持 AI SDK 7，可在 ADR 中替换 |
| OpenRouter | `@ai-sdk/openai-compatible` 或其官方社区包（实现时核实 v7 兼容性） | |

| ChatGPT/Codex 订阅 | 见 §4 | |

**提供商预设**是产品自有的一张小表：显示名、图标、默认 Base URL、使用的适配包、兼容参数、获取密钥的帮助链接、中国大陆是否可直连。新增提供商只改这张表（及必要的兼容参数），不改运行时。

2026-10-02 按用户要求导入一代项目的提供商品牌 SVG 素材，统一经前端 `Icon.tsx` 渲染。对话模型选择器（当前值及选项）、空白会话模型状态、设置档案、提供商/模型候选、用途分配、订阅账号和团队档案标识使用实际档案的 `provider` 对应 Logo；ChatGPT 使用 OpenAI Logo。自定义兼容接口与未知提供商使用中性备用素材，不根据模型名猜测提供商。素材本地打包、离线加载；单色图标适配深色主题，彩色素材保留原色。接入来源与验收见 [提供商 Logo 验收](acceptance/provider-logos-2026-10-02.md)。

**多轮思考内容回传**因提供商与路由而异（2026-09 核实：DeepSeek 官方包对新模型回传 `reasoning_content`；经 openai-compatible 路由曾出现回传缺陷）。遇到具体提供商的回传问题时，录制"带思考的多轮 + 工具调用"的回放加进回归测试，不要求每个预设都预先录制（[14 §2](14-quality.md#2-测试怎么写)）。

## 3. 供应商连接与模型（2026-10-12 改造）

目标：先添加供应商连接，再在该连接中添加模型。连接是独立持久化实体，不再通过模型名或域名临时分组。配置按下述连接与模型职责分层。旧版逐模型连接数据在启动时迁移。

### 3.1 数据职责

- `ProviderConnection`：稳定 `id`、用户命名的 `name`、预设/接口类型 `provider`、`baseUrl`、加密凭据引用、`extraHeaders`、订阅账号引用、远端模型目录缓存和更新时间。同一品牌可以建立多个连接，例如不同网关、账号或 Key；禁止仅按域名合并。
- `ModelProfile`：保留原 `id`，关联 `connectionId`，保存实际 `model` ID、可选别名、上下文 `contextWindow`、输出上限 `maxOutputTokens`、`reasoning`、模型级能力覆盖、`providerOptions`、`maxConcurrency`、默认标记。模型本身不再持有 URL、Key 或请求头。
- 显示以实际模型名为主，别名与供应商连接名为辅；默认模型、子代理和压缩模型继续引用模型档案 ID。
- API 只返回是否已配置凭据及掩码，不把密钥回传前端。编辑时省略 Key 表示保留，明确清除才删除连接的凭据关联。

### 3.2 页面与操作链

1. 页面主操作为「添加供应商」。表单填写连接名称、接口类型、URL、Key；高级连接设置放额外请求头。采用现有组件与错误提示，不另造弹窗框架。
2. 每个连接是一张独立卡片，标题显示名称、接口类型、URL 和模型数，提供「编辑连接」「刷新模型列表」「添加模型」。空连接也能显示，不要求先创建一个假模型。
3. 「添加模型」只需搜索、选择该连接目录中的模型；列表未包含时可手填模型 ID。名称默认等于模型 ID，不强制再填写别名。
4. 高级模型选项折叠展示：上下文、最大输出、图片输入能力、思考能力/强度、工具能力、提供商选项和现有并发限制。每项明确「自动/继承目录」与「手动覆盖」。当前内核支持文本和图片输入、文本输出；不提供实际上不能使用的音频/视频开关。
5. 模型行提供设默认、能力测试、编辑模型、删除模型。编辑模型不再出现 URL/Key。主对话与重试选择器按照连接分组，条目仍显示模型名；用途选择器也统一此命名。
6. 修改连接 URL/Key/请求头会提示影响该组全部模型；下一次模型请求使用新配置，正在执行的请求沿用创建时的配置。删除非空连接先要求移走或删除模型，不能静默连带删除。被默认/代理用途引用的模型继续执行现有引用检查与替换流程。

### 3.3 模型目录与能力

- 远端模型列表以连接为单位拉取和缓存，模型编辑器共享列表。显示最后成功更新时间、加载和失败状态。刷新失败保留旧列表；目录下架某个 ID 不自动删除已有模型。
- 模型目录的上下文/输出上限/能力只提供默认值；手动覆盖优先。没有证据时显示未知，不能默认为支持。
- 连接变更使该连接的远端目录与旧能力探测证据失效，但不清除用户手动能力覆盖。重新探测后更新来源与时间。
- 目录拉取成功只表示目录可访问，不冒充模型推理或多模态测试通过。

### 3.4 后端与真实请求

- 新增连接 CRUD 与按连接列出/刷新远端模型目录的契约端点；模型 CRUD 改为引用 `connectionId`。在 `protocol` 中统一请求、响应及客户端类型，前端不拼接私有 API。
- 配置装配层将连接与模型合成为 `ResolvedModel`。模型网关继续使用现有 AI SDK 适配器，不引入自写协议。
- 补上现有断线：`maxOutputTokens` 从编辑器、数据库、解析后的模型一直传到 `streamText`。空值代表采用目录默认/不显式覆盖；正整数检查在契约层完成。已知上下文时，输出上限不能大于上下文。
- 上下文进入预算/压缩判断；图片能力进入现有图片发送逻辑；思考强度按既有 provider 适配发送。界面中能力证据与请求控制分别说明，不能用一个徽标冒充已经传参。
- ChatGPT 订阅账号仍由独立账号页登录和刷新；每个账号对应连接，自动创建的模型引用连接，不复制订阅凭据，不改变已有授权范围。

### 3.5 旧数据迁移与发布

- 在应用持有原有实例锁时执行迁移，先保存可恢复的数据库备份。主密钥沿用原文件，不重新生成。结构与数据变更在事务中完成，失败回滚并明确报错，不带半迁移状态启动。
- 分组身份由接口类型、有效 URL、认证类型/实际凭据身份、请求头共同决定；相同 URL 不足以认定相同连接。相同凭据但不同模型可以合并；不同 Key、账号、请求头分别建立连接。凭据相等判断只在进程内进行，不记录明文或指纹到诊断输出。
- 保留所有模型 ID、模型参数、默认标记、能力手动覆盖和用途引用；自动生成可区分的连接名称。迁移完成后旧逐模型连接字段不再是读写来源，模型新写入只能关联连接。迁移可重复启动，不重复生成连接或丢失引用。
- 订阅账号模型单独按账号身份归组。迁移无法解密或无法归属时保留原始数据并中止迁移，禁止猜测合并。
- 开发与验证在当前云端源码完成；完成后通过既有 MCP 部署。生产切换需要重启后端，先告知用户。回滚需要源码与迁移前数据库成套恢复，不能只回滚前端文件。

### 3.6 验证重点与完成条件

- 迁移实测：多个模型共享连接、同 URL 不同 Key、订阅连接、旧默认与代理绑定、重复启动、失败回滚；不打印凭据。
- 真实 HTTP 配置测试：先建空连接，再添加多个模型；连接改动被所有子模型解析使用；目录失败保留缓存；删除/引用限制正确。
- 网关请求捕获：证明上下文、最大输出、图片开关和思考设置经过实际代码生效；不只断言表单有字段。
- 前端：空状态、添加/取消/重开、模型搜索和手填、高级选项清除回自动、连接共享编辑、长名称与窄窗口、默认选择、重复操作和失败提示。
- 静态检查、已有测试及构建通过，再部署到公网做浏览器回归；真实模型仅做小规模验证。完成时分别报告已通过、未验证和待用户操作项。

用途分配仍为主对话、子代理默认与上下文压缩摘要；未选择独立档案时沿用现有默认逻辑。此改造不改变 agent 的工具选择策略。

实现说明：REST/同步协议版本为 4。迁移在既有 openDb 之后、实例锁内执行，以 meta 中的 provider_connections_v1 为完成标记；DDL、数据回填与标记在同一事务中。迁移前使用 SQLite VACUUM INTO 生成包含 WAL 已提交数据的快照，保留模型表和 ID，删除旧连接列。旧客户端需与后端一起更新，浏览器刷新后使用新契约。

## 4. ChatGPT/Codex 订阅登录

### 4.1 要求【硬性】

- 两种登录方式：浏览器授权（PKCE，本机回调）与设备码（远程或无法打开浏览器时）。
- 令牌加密存储（[10 §4](10-data.md#4-密钥硬性)），自动刷新；刷新失败时界面提示重新登录。
- 界面明确标注：这是通过订阅账号访问的非公开接口，可用模型以登录后的发现结果为准，接口可能变化。
- 登录成功后自动创建对应的模型档案（可删除、可改名）。

### 4.2 实现【推荐】

2026-09 社区已有面向 AI SDK 7 的 ChatGPT/Codex 订阅 provider（如 `@grikomsn/ai-sdk-provider-chatgpt-oauth`：PKCE、可自定义凭据存储；以及另外两个更早期的包），但都处于早期（发布不久、使用者很少）。做法：

1. M0 评估上述候选：是否支持自定义凭据存储（必须，凭据要存进我们的加密库）、模型发现、流式工具调用、思考摘要。
2. 满足要求则**锁定精确版本**使用，并将其包在我们的 `SubscriptionProvider` 接口之后。
3. 都不满足时，写一个薄适配：OAuth 流程由我们的认证模块处理（标准 PKCE 与设备码流程），请求使用官方 `@ai-sdk/openai` 的 Responses 实现，通过自定义 `baseURL` 与 `fetch` 注入订阅接口所需的请求头与参数约束。适配代码限制在约 300 行以内，协议解析仍由官方包完成。

### 4.3 其他订阅（P2）

Claude Pro/Max、GitHub Copilot、国产订阅（如腾讯系、阿里系编程订阅）等，走同一个 `SubscriptionProvider` 接口接入。v1 不实现。

## 5. 模型目录

- 【推荐】使用 **models.dev**（MIT 许可的开源模型元数据库，提供上下文窗口、输出上限、价格、模态、工具调用与思考能力；有静态 JSON API，opencode 在使用）。
- 构建时下载一份快照打包进应用（离线可用）；设置中可手动"刷新模型目录"联网更新；更新失败不影响使用。
- 产品维护一个小的覆盖文件，用于补充 models.dev 缺失或不准确的条目（尤其国产模型），覆盖文件中的每一条注明来源链接与核实日期。
- 目录只提供默认值与"官方声明"类证据；实际能力以探测和用户覆盖为准。

## 6. 能力探测【推荐】

添加档案或手动触发时运行，结果缓存，键为 `(提供商, Base URL, 模型, 凭据指纹)`——凭据变化则缓存失效。

| 能力 | 方法 | 判定 |
| --- | --- | --- |
| 连通 | 发送"只回复 OK" | 收到回复 |
| 工具调用 | 提供一个合成工具，要求模型调用并回传一个随机标记 | 收到合法的工具调用且参数中包含该标记 |
| 视觉 | 生成一张随机排列的色块图片，要求模型按顺序说出颜色 | 顺序全部正确（随机生成，防止盲猜） |
| 思考 | 请求开启思考 | 返回中出现思考内容 |

- 探测不执行任何真实工具，单项超时 20 秒。
- 探测结果在界面显示（✓ / ✗ / 未知），用户可手动覆盖（记为 `manual`）。
- 运行时据此裁剪：不支持工具调用的模型不能作为代理模型（界面阻止并说明）；不支持视觉时 `workbook_render` 不出现在工具列表，图片附件不发送。

## 7. 其他

- **连接测试**与**拉取远端模型列表**（调用提供商的模型列表接口，按提供商使用正确的鉴权头）。
- **代理设置**：支持系统代理环境变量与设置中的 HTTP(S) 代理（通过自定义 `fetch` 注入），可设置不走代理的地址。
- **费用估算**：按模型目录价格和实际用量估算，界面标注"估算"。
- **限流**：按档案的 `maxConcurrency` 排队；收到 429 时按 `Retry-After` 退避（[04 §9](04-agent-runtime.md#9-错误与重试)）。
