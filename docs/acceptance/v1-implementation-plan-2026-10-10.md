# V1 收口执行计划（2026-10-10）

## 已确认范围

依据 `docs/01-product.md`、`docs/14-quality.md`、`docs/15-milestones.md` 与现有 ADR，在现有实现上增量完成 V1；不复制旧项目。执行方式为当前云工作区直接开发，不创建其他执行任务，不部署、不推送远端。交付源码与可复现验收记录。

“静态开发”表示不依赖浏览器进行开发与自动化验证，不表示把 Node/SQLite/WebSocket 产品替换为静态演示页。

## 顺序与证据

- [x] 基线：锁定现有依赖、执行 `pnpm check:all`，分类记录真实失败与环境限制。
- [x] 工作簿与沙箱：复核历史写回/冲突失败、QuickJS 退出清理；先添加或复现回归，再修复。
- [x] 文件闭环：protocol 定义文件管理请求/响应；server 复用 files 工具的备份、路径、活文档守卫；web 文件面板提供新建目录、重命名、回收站删除。真实 HTTP/SQLite 验证拒绝越界、未确认删除、冲突与成功后的文件内容。
- [x] 契约与渲染：由 protocol 契约生成 OpenAPI schema；补文档渲染 REST 与开发/测试响应校验，不复制 DTO 定义，不伪造无渲染端时的 PNG。
- [x] 可观测性：结构化日志按天落盘；诊断追踪/导出只含白名单元数据，拒绝输出凭据、提示词和文件内容；补真实边界回归。
- [x] 可靠性与协作：核对重启恢复、12 文件多代理、并发修订、预算约束；不足处补真实边界测试及实现。
- [x] 前端与桌面：核对 M6a/M6b P0 入口、空状态、键盘语义；补可自动验证项，构建桌面产物；不把 Linux 编译当作 Windows/macOS 实机验收。
- [x] 交付：执行最终完整门禁、diff 检查；附各场景的通过/失败/未执行状态、源码包、启动说明与仍需外部条件的发布事项。

## 全局约束

TypeScript strict / Node >=24 / pnpm 10.11.0；维持现有依赖方向、许可证、网络安全和路径约束。无新增安全例外。用户可见文案集中；不增加 P2 功能。文档未定的产品行为保留待决项，不擅自改写产品承诺。

## 重点失败条件

路径穿越、外指符号链接和已打开工作簿的移动/删除必须被拒绝；批量文件操作失败应回滚；无渲染端应有清晰错误；诊断导出不能含敏感内容；断线/进程退出不能自动重放有副作用操作。

## 发布证据边界

真实浏览器 QA、真实账号 OAuth、三个真实模型/40任务、macOS 与 Windows 签名安装包及更新演练依赖当前工作区之外的条件。未执行项明确保留，不以单元测试或构建替代，不宣称正式 V1 发布验收全通过。

当前实际覆盖、推荐项差异和外部验收限制统一记录在 [V1 交付验收](v1-2026-10-10.md)，不因勾选代码步骤而宣称正式发布。
