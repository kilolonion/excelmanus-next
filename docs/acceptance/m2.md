### 前端 doc.op 应用方式（选定方案）

只读工作台保留 `wb.setEditable(false)`（防止本地编辑造成静默分叉）；收到 `doc.op` 后**防抖 150ms 重取快照并重建本地 Univer 实例**（`scheduleDocRefresh` → `reloadDocument` → `doc` 对象替换触发 `useEffect` 重建）。`setEditable(false)` 下 mutation 命令会被权限拦截，`{fromCollab:true}` 不保证绕过，故采用确定性的快照重载方案；rev 显示来自快照 `document.rev`，`reduceDoc` 维护 `{rev, pending}`。

### 实现要点

- `documents` 增 `head_rev`/`checkpoint_rev`/`engine_version`；`doc_ops(doc_id,rev)` 持久化 base_rev/source/session/tool_call/write_set/mutations/inverse，写日志与 `head_rev` 同事务，提交后才广播。
- `DocumentService.submit` 串行队列；`baseRev` 后结构修订先把本次写入坐标平移（`transformChangeOp`/`transformMutation`，`cellValue`/`range`/`ranges` 参数重键），无法确定平移或目标被删 → 拒绝；区域冲突 details 含 `rev/source/cells(≤50)`。
- `workbook_edit`：effect=write/replay=unsafe/60s；`baseRev = 显式 ?? 读集 minRev ?? head`；成功后写集并入读集；`create` 返回 `UNSUPPORTED_FEATURE`；冲突带 hint「只重读这些区域后再写」。
- `workbook_read` range/search 记读集进 `ToolContext.reads`（每代理一份内存表）。
- `recoverInterruptedAgents` 调 `ToolDefinition.recover`；`workbook_edit.recover` 查 `doc_ops` 中 `tool_call_id` 命中即幂等 ok。
- WS：`sub doc:<id> cursor=rev` 从 `doc_ops` 补发 `doc.op`（约 500 格/mutation 分片 `chunk{index,total}`）后切实时；cursor>head → `doc.reload`；`doc.submit` → `doc.ack`/`doc.reject`；广播含提交者本人。

### 与 docs 的偏离 / 本轮省略

- 07 §3.3 完整流程里的写租约（lease）、文件自动备份、对象层（图片/图表写出）、公式重算等待本轮省略：文档尚无写回 xlsx（重启靠 doc_ops 重放恢复），备份在写回文件时（M2b）才有意义。
- 行/列结构操作的冲突写集只记插入/删除条带（尾部位移由 structural 变换承担），否则 stale 写无法平移而全冲突。
- 用户 mutation 提交的读集 = 其写集（11 §3.4）；坐标无法确定性平移的 mutation 在 stale + 结构历史存在时直接拒绝而非尽力猜。
- `checkpoint_rev` 恒为 0（尚无快照检查点）；`presence` 主题未实现。
- 前端采用快照重载而非逐 mutation `executeCommand`（见上）。

### 已知缺口

- 本地无写回 xlsx 文件（文档变更只在内存 + doc_ops）；进程重启后回放恢复。
- `doc.op` 大修订分片按 mutation 条数粗切；无 doc 级 `unsub` 之外的流控。
- `moveRange` 结构变换占位未实现（M2a 不生成该操作）。
