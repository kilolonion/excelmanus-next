# 07 表格引擎（活文档）

表格引擎是技术风险最高的部分。本章给出目标、推荐方案与备选，并在 §12 列出 M0 必须完成的技术验证。整体范式见 [03 §3.2](03-architecture.md#32-活文档工作簿在内存中被共同编辑)。

## 1. 目标

| 目标 | 级别 |
| --- | --- |
| **不破坏文件**：修改工作簿时，未被修改的内容（图表、图片、透视表、宏、切片器、迷你图、批注、外部链接、自定义 XML 等）原样保留 | 硬性 |
| 做不到保留时**拒绝**该操作并说明原因，而不是静默丢失 | 硬性 |
| 用户编辑、代理工具、脚本走**同一条写入路径**（文档 actor） | 硬性 |
| 用户、代理、截图、所有客户端看到的是同一文档的同一修订 | 硬性 |
| 代理的写入实时出现在用户的工作台上 | 推荐 |
| 写入后公式立即有计算值（增量重算）；公式较多的工作簿为异步完成（[ADR 0002](decisions/0002-formula-recalc-async.md)） | 推荐 |
| 5 万行级别流畅编辑；百万行级别可读、可分析 | 推荐 |

## 2. 文档模型的选择

### 2.1 决定【推荐，需 M0 验证】

**服务端用 Univer 无头实例作为活文档的内存模型**，文档操作就是 Univer 的 mutation（JSON 可序列化）。

2026-09 核实的事实：

- Univer 开源版（Apache-2.0，1.0.x）可在 Node 无头运行；公式引擎基于依赖分析与标脏做增量计算，并提供计算开始/结束事件。
- 前端可监听用户编辑产生的 command/mutation（`CommandExecuted` 事件，含 `id`、`params`），官方示例即以 JSON 转发；另一个实例可用 `executeCommand(id, params, { fromCollab: true })` 复现。
- 快照可导出（`save()` / `getSnapshot()` → `IWorkbookData`）并用于重建。
- 开源版**不含**多用户服务端协同（OT、修订管理）、xlsx 导入导出与图表，这些在 Pro 商业版中，我们不能使用。因此服务端排序、冲突检测、xlsx 编解码、图表都由我们实现。

收益：

| 收益 | 说明 |
| --- | --- |
| 天然一致 | 工作台、代理读取、公式计算、截图用同一个模型和同一个引擎 |
| 少一层映射 | 前端编辑产生的 mutation 直接发送到服务端应用；服务端的 mutation 直接广播给前端 |
| 公式免费 | 增量重算由引擎提供 |

风险与对策：

| 风险 | 对策 |
| --- | --- |
| 与 Univer 内部格式耦合，升级可能改 mutation 格式 | 两端锁定同一精确版本；文档日志记录 Univer 版本；升级时运行"旧日志回放"测试；检查点后的日志可清空，降低跨版本回放需求 |
| 超大工作簿内存占用 | 设定活文档的单元格上限（M0 测定，初设 500 万个非空单元格）；超出时以"只读大文件模式"打开（§6.4） |
| Univer 不建模的对象（图表、透视表等） | 由我们的**对象层**（§4.3）持有并维护锚点 |

### 2.2 备选

若 M0 验证不通过（性能、内存、mutation 可靠性），切换为：**自有稀疏模型 + 自有操作格式**，Univer 只作前端视图与服务端公式计算器；需要实现"Univer 命令 ↔ 自有操作"的双向映射，并限制工作台允许的编辑命令集合。切换只影响 `modules/workbook` 内部，文档 actor 的对外接口（§3.2）不变。

## 3. 文档 actor

### 3.1 生命周期

1. **打开**：首次被订阅或被工具访问时，在文档 worker 中创建。读取文件 → 编解码为 Univer 快照 + 保留清单（§4）→ 若文档日志中有晚于最后检查点的操作，按顺序重放 → 就绪。
2. **运行**：串行处理提交、读取、截图请求。
3. **检查点**：见 §5。
4. **卸下**：无订阅者且空闲 10 分钟 → 检查点 → 释放内存。

### 3.2 对外接口（示意）

```ts
interface DocumentService {
  open(ref: FileRef): Promise<DocHandle>;                         // 返回 docId 与当前 rev
  read(docId, req: ReadRequest): Promise<{ rev: number; data }>;  // workbook_read 的各种投影
  submit(docId, batch: {
    baseRev: number;
    readSet: RangeSet;             // 提交者依据读过的区域
    source: { kind: "agent" | "user" | "script"; id: string; toolCallId?: string };
    ops: ChangeOp[] | UniverMutation[];   // 代理/脚本给 ChangeSet，工作台给 mutation
    dryRun?: boolean;
  }): Promise<SubmitResult>;       // 成功：新 rev、写集、重算结果、变更摘要；失败：冲突详情
  snapshot(docId, window?): Promise<Snapshot>;                    // 工作台与截图
  subscribe(docId, afterRev): AsyncIterable<DocOpEvent>;
}
```

### 3.3 一次提交的处理

```
接收提交
 → 检查文件租约（[05 §6](05-multi-agent.md#6-文件租约防止多个代理改同一个文件)）
 → 冲突检查：baseRev 之后各修订的写集 ∩（本次读集 ∪ 本次写集）= ∅？结构操作按 [03 §6.1](03-architecture.md#61-文档内) 变换坐标
 → 代理/脚本来源：若本会话首次修改该文件，先创建修改前备份（§7）
 → ChangeSet 编译为 Univer 命令并执行；按写集保存前像并生成逆操作（不使用 Univer 内置撤销；含 remove-sheet/move-range 的修订标记为"需快照回滚"，[ADR 0003](decisions/0003-univer-server-document-model.md)）
 → 工作台来源的 mutation：先经传输修补（样式子集、筛选资源对账）再复现
 → 对象层同步（结构操作平移图表锚点与数据引用；不能保证正确则整批回滚并拒绝）
 → 公式数 ≤ 阈值（初设 5,000）：等待公式增量计算完成，收集写入公式的计算值与错误；否则不等待，公式单元格标记 pending
 → dryRun：执行逆操作回滚，返回将产生的变更与预览数据，不写日志、不广播
 → 否则：写文档日志（rev、来源、写集、mutation、逆操作）→ 广播 → 安排检查点
 → 异步重算完成后：公式结果作为后续修订提交（source.kind = "engine"），走同一写入路径
```

公式计算在独立于文档 actor 的线程中运行，重算期间读取、提交与广播不被阻塞（[ADR 0002](decisions/0002-formula-recalc-async.md)）。

- 大批量写入（如 10 万个单元格）作为一个修订提交，但广播时按约 500 个单元格分片推送，工作台逐步显示。
- 一次提交的上限：20 万个单元格（可配置），超出返回 `LIMIT_EXCEEDED` 建议分批。

## 4. xlsx 编解码

### 4.1 现状（2026-09 核实）

ExcelJS 上游停在 4.4.0（2023-10）且读后写回会丢弃图表等部件；SheetJS CE 写入不支持样式；`xlsx-populate` 路线正确但 2020 年停更，其 TS 重写版刚起步；没有成熟的全保真 JS/TS xlsx 库；Univer 的 xlsx 导入导出属于 Pro。**因此编解码必须自研**（可在 M0 评估复用上述库的部分解析代码）。

### 4.2 方案：快照 + 保留清单【推荐】

**导入**：xlsx（ZIP）→

- **Univer 快照**：Univer 能建模的内容——单元格值与公式、样式、合并、行高列宽、隐藏、冻结、条件格式、数据验证、定义名、超链接等。
- **保留清单**：每个包部件的原始字节与哈希；工作表 XML 中 Univer 不建模的元素（`extLst`、迷你图、切片器引用、`x14` 扩展等）及其在 XML 中的位置；样式表中原始的样式索引与主题。
- **对象层**：图表、图片、形状、透视表、切片器、批注的 OOXML 与锚点（§4.3）。

**导出（检查点）**：

- 每个工作表记录"自上次检查点以来是否被修改"。未修改的工作表 XML 与所有未涉及的部件**逐字节复制**。
- 被修改的工作表：根据快照重新生成单元格区（`sheetData`）等 Univer 建模的部分，并把保留清单中的未知元素按原位置插回；样式追加到 `styles.xml` 末尾，不重排已有样式索引。
- 同步更新 `[Content_Types].xml` 与关系文件（新增/删除的图表、图片）。
- 写入临时文件 → 重新解析被修改部件并抽样比对单元格值 → 原子改名覆盖原文件。

**写入前可判定的拒绝**：会使一致性无法保证的操作在提交时（§3.3）就拒绝，而不是在检查点时才失败，例如：结构操作穿过透视表源区域、合并区与表对象冲突、修改被数字签名覆盖的部件而用户未确认。

### 4.3 对象层

Univer 开源版不建模图表、透视表、切片器等。对象层负责：

- 持有这些对象的 OOXML 与锚点（起止单元格 + 偏移）。
- 结构操作时平移锚点和图表数据引用（`Sheet1!$B$2:$B$20` 等）；无法确定性更新时拒绝该结构操作。
- 新建图表：由我们的图表生成器输出标准 DrawingML（柱、条、折线、饼/圆环、散点、面积、组合）。
- 为工作台提供对象的位置与简要信息，工作台在对应位置显示占位框（类型、标题）；图表预览图（用开源图表库按图表数据绘制）为 P1。

### 4.4 保真等级表【硬性：每项必须有明确等级】

| 特性 | 读取 | 修改文件其他部分时 | 编辑该特性本身 |
| --- | --- | --- | --- |
| 值、公式、共享公式、数组公式 | ✓ | 保留 | ✓（数组公式 P1） |
| 样式、数字格式、主题色 | ✓ | 保留 | ✓ |
| 合并、行高列宽、隐藏、分组、冻结 | ✓ | 保留 | ✓ |
| 条件格式、数据验证 | ✓ | 保留 | ✓ |
| 定义名、表对象 | ✓ | 保留 | ✓（P1） |
| 图表 | 元数据 | 保留（锚点随结构操作平移） | 新建常见类型 ✓；修改标题/数据范围 ✓ |
| 图片 | 元数据 + 提取 | 保留 | 新增 ✓；删除 P1 |
| 透视表、切片器、时间线 | 元数据 | 保留（结构操作影响其源区域时拒绝） | ✗ |
| 迷你图、x14 扩展 | 元数据 | 保留 | ✗ |
| 批注 / 备注 | ✓ | 保留 | P1 |
| 宏（xlsm） | 是否存在 | 保留 | ✗ |
| 外部链接 | 引用清单 | 保留 | ✗ |
| 数字签名 | 是否存在 | 修改后签名失效，提交前明确告知 | ✗ |
| 加密工作簿 | ✗（提示需先解密） | — | — |

### 4.5 其他格式

| 格式 | 处理 |
| --- | --- |
| CSV/TSV | 作为单工作表活文档打开。编码识别（UTF-8、UTF-8 BOM、GBK/GB18030）、分隔符识别；检查点写回时保持原编码与分隔符，不引入格式（样式修改被拒绝并建议另存为 xlsx） |
| `.xls` / `.xlsb` | 【开放】v1 支持"导入为新的 .xlsx"（值 + 基本格式，报告丢失项）；候选 SheetJS CE（Apache-2.0，需评估其安全公告与版本来源） |
| `.ods` | P2 |

## 5. 文档日志与检查点

- **文档日志**（SQLite 表，[10 §3](10-data.md#3-数据库结构推荐表的划分与关键约束列名可调整)）：每个修订一行——修订号、来源（用户/代理/脚本及 ID）、`baseRev`、写集、mutation、逆操作、时间。提交成功 = 日志写入成功。
- **检查点**：把当前模型保真写回 xlsx（§4.2），记录"已写回到 rev N"及写回后的文件哈希。
  - 代理/脚本提交后 1 秒内；用户编辑停止 2 秒后；文档卸下、应用退出时。
  - 检查点失败（磁盘满、文件被占用）：日志保留，界面提示，稍后重试；不丢数据。
- **崩溃恢复**：打开文档时，若日志中有晚于最后检查点的修订，先载入文件再重放这些修订，然后立即检查点。
- **日志保留**：检查点完成且没有代理的读集依赖更早修订后，更早的日志可以清理（保留最近 24 小时或最近 1,000 个修订，用于冲突检测与变更摘要）。日志不是面向用户的历史功能。
- **外部修改**：监听文件变化。文件哈希与最后检查点不一致时：
  - 无未写回修订 → 重新加载，修订号继续递增（记一条"外部重新加载"修订，写集为全表），读过该文档的代理收到通知；
  - 有未写回修订 → 暂停检查点，界面让用户选择"保留应用中的版本"（外部版本另存到备份区）或"载入外部版本"（应用中的版本另存到备份区）。

## 6. 读取

### 6.1 投影

`workbook_read` 的各模式（[06 §4.1](06-tools.md#41-workbook_readread)）都从活文档当前修订读取，返回修订号。代理读过的区域由运行时记入该代理对该文档的读集（用于冲突检测与变化通知）。

### 6.2 覆盖状态

每个维度报告：`not_requested` / `empty` / `unsupported` / 已加载（可 `partial`）。三者不能混为空列表。

### 6.3 显示与公式

- 显示文本（数字格式渲染）由 Univer 的格式化逻辑产生，与工作台一致。
- 公式单元格分开报告：公式文本、文件中的缓存值、引擎计算值；引擎不支持的函数明确列出。
- 单次返回上限：约 2,000 个单元格或 16,000 字符，超出分页。

### 6.4 只读大文件模式

超过活文档上限的工作簿不载入 Univer，而是由编解码层流式读取：支持总览、分页读取区域、搜索、分析（装入 SQLite）；不支持编辑与工作台编辑（工作台以只读分页表格展示）。代理修改这类文件时，引导其用 `workbook_analyze saveTo` 或 `run_script` 生成新文件。

## 7. 修改前备份

替代旧版的修订历史与撤销，不对用户承诺操作级撤销。

### 7.1 规则【硬性】

- 在一个会话中，代理或脚本**第一次修改某个已有文件**（不是本会话中代理新建的文件）之前，运行时自动保存该文档此刻的状态为备份（如有未写回修订，先检查点）。同一会话内后续修改同一文件不再备份。
- 由运行时强制执行，不依赖模型记得复制；模型可以选择另存为新文件，则不需要备份。
- 工具结果告知备份位置。
- 删除文件移入回收站。
- 用户在工作台中的手动编辑默认不产生备份（设置中可开启）。

### 7.2 存储

```
<工作区>/.excelmanus/
  backups/<日期时间>_<会话短ID>/<原相对路径>
  trash/<日期时间>/<原相对路径>
```

数据库记录每个备份：原路径、备份路径、会话、代理、时间、大小、哈希。

### 7.3 保留策略【推荐】

每个文件保留最近 20 个备份；超过 30 天自动清理；工作区备份总量超过 2 GB 时提示。用户可查看、另存、删除备份或"用备份替换当前文件"（替换前当前状态也先备份；替换作为一个"外部重新加载"修订进入文档）。

### 7.4 "修改前的值"

变更高亮时显示的原值，优先由本轮修订的逆操作得出（精确且无需读文件）；日志已清理时再与备份比对；都不可用则不显示。

### 7.5 批次撤销（内部机制）

文档 actor 为每个修订保存逆操作。它只用于系统内部的失败回退（例如多文档批次中后一个文档提交失败时回退前一个，[03 §6.3](03-architecture.md#63-跨文档)），**不作为面向用户的撤销功能**。是否在将来开放"撤销代理的上一次修改"作为产品功能，列入 [附录 C](appendix-c-open-questions.md)。

## 8. 工作台与截图

- 工作台订阅 `doc:<id>`：先取快照，再接收修订流；用户编辑产生的 mutation 以 `baseRev` 提交，服务端确认或拒绝（拒绝时前端撤销本地变更并提示冲突，见 [02 §4.7](02-interaction.md#47-用户与代理同时编辑硬性)）。
- 代理的写入按修订流实时出现，并驱动活动叠加层的"已修改"高亮。
- 大工作簿的快照按需加载（先加载可见工作表与可见窗口，【开放】具体策略由 M0 测定）。
- 截图：渲染池加载只读渲染页，载入指定修订的快照（或其可见窗口），截取区域，返回 PNG、修订号、行列与像素的映射及渲染限制（如对象层的图表显示为占位框）。

## 9. 数据分析

- SQLite 内存库，在 worker 中运行。来源（工作表、区域、CSV）按 `(docId, rev, 区域)` 装载为表并缓存：列名来自表头（去重、清理），每列推断类型并保留原始文本列。
- 只读 SQL；`saveTo` 时把结果作为 ChangeSet 提交到目标文档（新工作表或新文件）。
- 单次装载上限 100 万行（可配置）；更大数据为 P2（评估 DuckDB）。

## 10. 与代理的协作

- 代理读取时，运行时记录读集 `(docId, 区域, rev)`。
- 其他来源修改了与读集相交的区域后，代理在下一个步骤边界收到合并后的通知（[03 §6.2](03-architecture.md#62-文档与会话之间)）。
- 提交冲突时，冲突详情列出被改的单元格、修改者与修订号，代理只需重读这些区域。
- 成功截图也是观察：记录实际可见区域与截图修订，重启后可从工具结果重建。连续/分块重读的并集覆盖到的格视为已知；未覆盖的空洞和粗粒度读集仍保留保护。显式 `baseRev` 仅声明本次操作的坐标依据，不能替代其他旧读集的重读。
- 工作台只提交用户命令触发的修改；本地公式内部状态和计算结果不能回送为 `user` 修订，服务端也拒绝这类提交。公式缓存由文档 actor 生成/发布。稀疏 mutation 的写集覆盖明确携带的格，不能用包围矩形把未修改格也算入（[ADR 0018](decisions/0018-workbook-observations-and-derived-mutations.md)）。

## 11. 限制与默认值

| 项 | 默认 |
| --- | --- |
| 活文档非空单元格上限 | 400 万（M0 测定，[ADR 0003](decisions/0003-univer-server-document-model.md)） |
| 单次提交单元格数 | 20 万 |
| 单次读取返回 | 2,000 单元格 / 16,000 字符 |

## 2026-10-10 实现覆盖与保真边界

对象层现已接入 doc.submit、共享 mutation、前像回滚、检查点和修改摘要。图表是原生 DrawingML；图片是原始媒体部件与锚点。条件格式/验证使用引擎原生资源，未知原始规则只保留。布局支持像素尺寸、隐藏与1–7级 outline 分组；结构插删影响不能建模的分组/对象时拒绝。

本轮测试包含：八类图表生成及 LibreOffice 打开、导入第三方图表只改标题且其余 ZIP 部件完全相同、图表删除、CF/DV 修改/移除与预览回滚、图片新增/字节回读/实际工具提取、分组/隐藏/排序、主题色与边框。确切测试结果见 [当前验收](acceptance/v1-2026-10-10.md)。这些测试不代表所有外部 Excel 文件均能编辑；原表中的保真目标不因此被取消。

SQL 不再在主线程同步执行任意查询：输入内存表通过 IPC 传给受限 Node 子进程，查询只读、限内存/规模，超时可杀死原生 SQLite 计算。没有开放任意 shell 工具。

### 2026-10-10 共享公式、筛选与超链接补充

共享公式在导入和填充时通过 Univer 官方词法器展开为显式单格公式，保持相对/绝对引用语义；缺失主公式时拒绝导入。筛选采用原生资源，写回 autoFilter 和隐藏行，支持枚举值及空值；复杂筛选原样保留但不解释。超链接存入 cell custom 并写回 OOXML 关系，支持 http/https/mailto/内部位置，不自动访问目标。工作表隐藏写回 state，至少保留一张可见表。自动适配采用无头确定性估算，不宣称与 Excel 字体测量相同。
