# 15 里程碑

原则：**每个里程碑结束时都有一个能端到端运行的产品**，只是能力范围不同。每个里程碑的退出条件以 [14](14-quality.md) 中对应的门禁与场景为准。

各阶段涉及页面设计时，使用 [16 §1.2 阶段索引](16-design-reference.md#12-对应环节) 查找对应工作台、对话和设置参考。草案不要求一比一复刻：M1 参考只读布局，M2 参考编辑与审批，M3 参考派发和恢复，M4 参考团队视图，M5 参考订阅与扩展设置；M6a 集中完成前端整体设计与收口，M6b 完成发布前打磨。按实际交付能力设计入口，不提前引入草案中的未定义功能，也不据此改变优先级或验收完成状态。

## M1 可行走的骨架

2026-09-30 状态：`af250b6` 已提交主要纵切；[修复记录](acceptance/m1-repair.md) 列明构建、安全与交互修复。最终工作树未验收，不能以原有 40 个测试通过代替 M1 全部退出条件。

目标：本机 Web 形态下完成"对话 → 读表 → 回答"。

- 单仓结构、契约包、依赖方向检查、CI 门禁框架。
- 后端：REST、设备令牌、SQLite 与迁移、设置、模型档案（API Key）、会话、**会话日志 + 投影框架 + 同步通道（会话主题，游标续传）**、能力模块接口与 actor 调度。
- 运行时：轮状态机、单代理、只读工具（`read`、`find`、`workbook_read`、`workbook_analyze` 无 `saveTo`）、重试、错误指引。
- 前端：布局、对话面板、工具卡片、只读表格工作台（打开工作簿、选区作为上下文、区域引用可点击）。
- 表格：只读的文档 actor（导入、快照、读取投影、`doc:` 主题的快照获取），为 M2 的编辑打基础。
- 提供商：OpenAI、Anthropic、DeepSeek、一个 OpenAI 兼容国产模型。

**退出条件**：验收场景 1、2、11、22；契约测试、同步通道回放测试在 CI 运行；性能基准首次测量并把 [01 §5.1](01-product.md#51-性能推荐目标值在-m1-结束时用基准测试确认后改为硬性) 的目标值确认为硬性（或调整）。

## M2 编辑闭环

目标：代理与用户都能安全地修改工作簿。

- **活文档**（文档 actor、文档日志、检查点、对象层、区域级冲突、`doc:` 主题与在线状态）、保真编解码、公式计算、修改前备份与回收站。
- 工具：`write`、`edit`、`files`、`workbook_edit`（含图表、条件格式、数据验证）、`workbook_render`、`workbook_export`、`workbook_analyze saveTo`、`present`、`todo`。
- 权限模式与审批（含表格预览层）、`ask_user` 全部题型（含区域确认/选取/修改确认）。
- 工作台编辑（与代理共用写入路径）、代理活动叠加层、变更摘要、变更导航与"修改前的值"、冲突处理。
- 文件面板、备份面板。

**退出条件**：验收场景 3、4、5、6、7、18、24、25；保真语料测试与文档并发模糊测试全量通过。M2b 的文件写回、备份、回收站、文本写入和另存验证见 [M2b 验收记录](acceptance/m2b.md)；M2c/M2d 的退出项仍未完成。

## M6 打磨与发布 v1

### M6a 前端整体设计与收口

目标：在 M1–M5 已接通的真实能力之上，集中完成一次前端整体重整，使工作台、对话、侧栏和设置中心成为统一、可连续使用的产品体验。该阶段不是只调整配色或补充零散按钮，也不以各阶段零散接入功能代替整体页面收口。

依据：[02 交互设计](02-interaction.md) 定义实际流程与状态，[16 页面设计参考](16-design-reference.md) 及其中存档的工作台、设置草图提供布局与视觉参考。开始时盘点现有页面、真实能力和交互缺口；在验收记录中简要说明草图中采用、调整和不采用的内容及原因，不做像素匹配。

- **整体布局**：统一工作台、对话面板、侧栏和设置中心的信息层级与入口关系；完成对话优先、打开工作簿后的分栏、拖动与折叠、比例记忆，以及 1024–1279px 的表格/对话切换。
- **视觉与组件**：统一字体、间距、颜色、边框、图标、控件、状态徽标和反馈；读取、待确认、已修改、审批、冲突和失败状态可区分，不只依靠颜色。
- **跨能力流程**：整体复核并补齐选区联动、区域引用、审批预览、变更摘要与定位、派发与恢复、团队与代理视图、文件与备份入口，以及完整设置中心的导航、搜索和保存反馈。
- **异常与可访问性**：统一空状态、加载、断线重连、中断、权限拒绝、冲突和结果不确定的表达；主要流程可用键盘完成，焦点可见，长中文、文件名、公式和审批理由不遮挡操作。
- **真实页面复核**：按 [14 §8](14-quality.md#8-页面设计参考的复核) 与 [16 §6](16-design-reference.md#6-页面复核与证据)，在真实浏览器、真实后端与真实 HTTP/WebSocket/SQLite 边界检查主要流程，模型输出可用假模型替代；保存实现截图或录屏及运行结果。

范围边界：M1–M5 各自要求的前端功能和真实边界验收仍在原阶段完成，不能顺延到 M6a；M6a 负责整体整合与复核。P1 仍按原优先级取舍，手机完整体验仍属 P2；不从草图新增未定义能力，也不把示例状态当作运行结果。

**退出条件**：工作台、对话、侧栏、设置中心完成整体复核；1024px、1280px 和更宽屏下关键操作可达、内容可读、状态可信，键盘操作与窄屏降级有实际证据；主要流程无阻断问题。结果、环境、证据位置和已知问题写入 `docs/acceptance/m6a-frontend.md`，未执行项不得标记通过。沿用 ADR 0006 的关键路径策略，不新增逐控件测试或像素匹配门禁；本规划不表示 M6a 已开始或通过。
