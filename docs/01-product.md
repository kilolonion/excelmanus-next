# 01 产品需求

## 1. 产品定位

ExcelManus 是一个**以表格为中心的 AI 代理工作台**。用户用自然语言描述任务，代理读取、分析、修改工作簿，并在同一界面里把它看了哪里、打算改哪里、实际改了什么直接标在表格上。

区别于"聊天窗口 + 文件附件"的通用 AI 助手，ExcelManus 的核心体验是：

1. **表格是一等公民**：用户和代理面对同一张表，选区、高亮、确认都在表格上完成。
2. **可控**：写入前可预览，关键操作需审批，原文件自动备份，版本冲突时拒绝覆盖。
3. **可协作**：复杂任务可拆给多个子代理并行处理，它们之间能互相沟通，用户能看到每个代理在做什么。

## 2. 目标用户与典型场景

| 用户 | 典型任务 |
| --- | --- |
| 财务、运营、行政等日常与表格打交道的办公人员 | 汇总多张报表、核对两份清单差异、按规则清洗数据、生成月报与图表 |
| 数据分析人员 | 快速探索数据、写复杂公式、做透视与分组统计、批量生成分析表 |
| 需要把纸质/截图表格数字化的人 | 把票据、表单截图转为可编辑的 Excel |

代表性任务（v1 验收场景的来源，见 [14 §5](14-quality.md#5-端到端验收场景硬性v1-发布前全部通过)）：

1. "读一下 sales.xlsx，告诉我每列是什么意思。"
2. "按地区汇总销售额，放到新工作表，并画柱状图。"
3. "比较两份报价单，列出价格变动和缺失项目。"
4. "把 C 列的日期格式统一成 yyyy-mm-dd，空值标黄。"（代理先高亮将要修改的区域并请用户确认）
5. "这张截图整理成 Excel，版式尽量一致。"
6. "这 12 个分公司的表，每个都按统一模板整理后合并成一份总表。"（主代理派出多个子代理并行处理，子代理之间就表头口径互相确认）
7. 用户在代理执行中发现方向不对，追加"先别改原表，另存一份"。
8. 代理执行到一半，用户关掉了浏览器；重新打开后看到任务仍在运行或已完成。

## 3. 功能清单与优先级

优先级：**P0** v1 必须有；**P1** v1 应该有，可在 v1 末期交付；**P2** 后续阶段，v1 只预留扩展点。

### 3.1 对话与任务执行

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| 流式对话 | P0 | 文本、思考过程（可折叠）、工具调用卡片实时显示 |
| 附件：图片、表格文件 | P0 | 粘贴、拖拽、选择文件；图片发给支持视觉的模型 |
| `@` 引用 | P0 | 引用工作区文件、工作表区域（带版本）、技能 |
| 当前选区作为上下文 | P0 | 用户在表格里的选区自动作为可移除的上下文附在消息上 |
| 运行中追加消息的三种策略 | P0 | 引导（steer）、打断（interrupt）、排队（queue），默认策略可设置，单条可覆盖 |
| 停止当前任务 | P0 | 独立于"打断"，只停止，不发送新消息 |
| 审批 | P0 | 按权限模式对写入、删除、外部工具调用请求批准；支持"本会话内同类操作自动批准" |
| 提问（ask_user） | P0 | 选项题、多选、自由输入；**可要求用户在表格上选取或确认区域**（见 [02 §4](02-interaction.md#4-代理与表格的联动)） |
| 待办清单 | P0 | 代理维护任务步骤，界面实时显示进度 |
| 上下文压缩 | P0 | 长对话自动压缩，也可手动触发；显示当前上下文占用 |
| 断线续传、重启恢复 | P0 | 见 [00 §2.4](00-principles.md#24-可恢复性) |
| 变更摘要 | P0 | 每轮结束根据实际文件变更生成摘要，可一键定位到变更 |
| 会话管理 | P0 | 新建、重命名、删除、搜索、导出为 Markdown |
| 从某条消息重新开始 | P1 | 截断之后的对话重新生成（不回滚文件，界面明确提示） |
| 斜杠命令 | P1 | `/model`、`/compact`、`/stop`、技能调用 `/<技能名>` 等 |

| 功能 | 优先级 | 说明 |
| --- | --- | --- |

| 新建工作簿 | P0 | 从零创建，含多表、样式与公式 |
| 条件格式、数据验证 | P0 | 创建与修改 |
| 原生图表 | P0 | 创建常见图表（柱、条、折线、饼、散点、面积、组合），可修改已有图表的数据范围与标题 |

| 截图查看 | P0 | 把区域渲染成图片交给视觉模型检查 |
| 格式转换与导出 | P0 | xlsx ↔ csv/tsv、按列值或行数拆分、导出 PDF（P1） |

支持的文件格式：`.xlsx`、`.xlsm`（保留宏）、`.csv`、`.tsv` 读写；`.xls`、`.xlsb` 只读或导入转换（【开放】：实现方式由表格引擎 spike 决定，见 [07](07-workbook-engine.md)）。

## 4. 明确不做（v1）

| 不做 | 理由 |
| --- | --- |
| Word 等其他文档格式 | 产品负责人决定聚焦表格 |
| 文件修订历史、版本回溯、撤销某次代理操作 | 旧项目半实现、承诺过重；由修改前备份替代 |
| Python 运行时 | 打包体积与复杂度；沙箱用 JS/TS |
| 任意 shell 命令执行 | 安全边界难以保证；需要时通过 MCP 接入 |
| 多用户、多租户、账号体系 | 单用户产品；服务器部署也是单实例单用户 |
| 迁移旧版数据 | 产品负责人决定全新开始 |
| 与 Microsoft Excel 像素级一致的渲染 | 做不到；如实标注渲染差异 |
| 执行 VBA 宏 | 安全原因 |

## 5. 非功能要求

### 5.1 性能【推荐】（目标值，在 M1 结束时用基准测试确认后改为【硬性】）

测试机基准：Apple M1 / 16 GB 或同级 Windows 笔记本。

| 指标 | 目标 |
| --- | --- |
| 桌面应用冷启动到可输入 | ≤ 3 秒 |
| 服务端给模型首次请求增加的额外延迟（不含模型本身） | ≤ 150 ms |
| 打开 5 万行 × 20 列的工作簿到首屏可见 | ≤ 2 秒 |
| 代理读取总览（5 万行工作簿） | ≤ 1 秒 |
| 对 5 万行做 SQL 分组聚合 | ≤ 1 秒 |
| 单次区域截图 | ≤ 2 秒 |
| 事件从产生到显示在界面 | ≤ 100 ms（本机） |
| 代理提交到工作台显示 | ≤ 200 ms（本机） |
| 用户单元格编辑提交确认 | ≤ 50 ms |
| 空闲时后端常驻内存 | ≤ 300 MB |
| 桌面安装包体积 | ≤ 250 MB |

### 5.2 可靠性【硬性】

- 进程崩溃不丢失已确认的数据（数据库使用 WAL，文件写入用临时文件 + 原子改名）。
- 任何写入工作簿的操作失败时，原文件保持原样。已确认的修改先写入文档日志，崩溃后可恢复。
- 同步通道断开后重连，不丢失、不重复展示。

### 5.3 安全【硬性】

- 本机服务默认只监听 `127.0.0.1`，每次启动生成随机访问令牌；浏览器打开本机地址后自动建立受 `HttpOnly` Cookie 保护的会话，CLI/桌面继续携带令牌（防止本机其他网页或程序调用）。
- 密钥（API Key、OAuth 令牌）加密存储；日志、导出、错误信息中不出现密钥。
- 模型生成的代码只在沙箱中运行，不能访问沙箱外的文件、网络和进程（见 [08](08-sandbox.md)）。
- 文件工具不能访问工作区以外的路径，不能跟随指向工作区外的符号链接。

### 5.4 隐私

- 除用户配置的模型服务与 MCP 服务外，不向任何第三方发送数据。
- 可选的崩溃报告与使用统计默认关闭（P2）。
