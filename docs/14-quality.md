# 14 质量

2026-10-11 起按小型开源项目的方式维护质量：**少而真实的自动化测试，加上发布前的手动冒烟**。旧版的门禁清单、25 个硬性验收场景、真实模型评测要求和"没有证据不算通过"的记录规则都已取消（旧内容见 git 历史；25 个场景仍逐条列在 [V1 验收记录](acceptance/v1-2026-10-10.md)，可作为手动验证的参考）。

## 1. 自动检查

CI 在每次推送和 PR 时运行，本地用 `pnpm check:all` 一次跑完。

| 检查 | 命令 | 说明 |
| --- | --- | --- |
| 类型检查 | `pnpm typecheck` | 根脚本加各包 `tsc --noEmit` |
| Lint 与格式 | `pnpm lint` | Biome，警告不阻断 |
| 依赖方向 | `pnpm check:deps` | 规则见 `scripts/dependency-matrix.ts` |
| 许可证 | `pnpm check:licenses` | 只允许宽松许可 |
| Web 构建 | `pnpm build:web` | 类型检查覆盖不到打包问题 |
| 测试 | `pnpm test` | Vitest；本机装了 LibreOffice 时额外实际打开生成的文件 |

桌面打包和"仓库外解压后 `--self-test`"在 CI 中改为手动触发（`workflow_dispatch`），发布前需要时再跑。

## 2. 测试怎么写

- 测试走真实代码：真实 HTTP、WebSocket、SQLite 文件和工作簿引擎。**假模型只替代模型服务的输出**，不替换我们自己的代码。AI SDK 的 mock 模型可以编排文本、思考、工具调用和错误。
- 在容易出错的地方补测试：区域运算、事件 reduce、冲突判定、写回与保真、崩溃恢复。修 bug 时先写一条能复现的测试。
- 新功能只要求现有测试继续通过，不要求每个功能都配集成测试。
- 不追求覆盖率，不写逐端点契约测试，不做验收矩阵和证据记录。
- 不写只在仓库里能过、换个环境就跑不起来的测试。
- 过时或成本远大于价值的测试可以删改，在提交说明里写一句原因。

## 3. 发布前冒烟清单

手动走一遍，约 15 分钟。发现的问题记到 [backlog](backlog.md)。

1. 用全新数据目录执行 `pnpm start`，首次引导能走完；添加模型档案，测试连接通过。
2. 发一条消息：流式回复、思考折叠、工具卡显示正常。
3. 上传或打开示例工作簿，表格显示正常，选区能作为上下文发给代理。
4. 让代理改表：审批预览 → 批准 → 表格更新 → 变更摘要能定位 → 修改前有备份。
5. 自己改几个单元格，刷新页面后内容还在。
6. 运行中追加消息、停止；断网后重连，对话不丢、不重复。
7. 设置中心各页能打开、能保存；深浅色切换正常。
8. 桌面版：`pnpm build:desktop` 后能启动，并完成第 2–4 步。

## 4. 可选（有条件时再做）

- **真实模型试用**：改了系统提示词、工具说明或技能后，用自己的模型在几个典型任务上试一下。完整评测集（40 个任务）在 `fixtures/v1-evals/`，执行器是 `scripts/evaluate-v1.ts`，会产生 API 费用；技能评测见 [skill-evals.md](skill-evals.md)。
- **浏览器复核脚本**：`packages/web/test/fixtures/*-browser.mjs`，配合假模型预览后端使用（见 AGENTS.md「命令」）；Playwright 需要从外部提供。
- **性能**：[01 §5.1](01-product.md#51-性能参考目标) 的数字只是参考目标，不设基准门禁；明显变慢时再处理。
- **保真**：用户反馈打不开或丢内容的文件，脱敏后加进 `fixtures/` 做回归。
