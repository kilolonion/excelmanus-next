# 14 质量与验收

## 1. 旧项目的教训

旧项目的三道门禁全部是"假绿"：API 覆盖率脚本只读了 1 个文件就报告 0 缺口（实际 84 个）；冒烟测试在仓库内运行，靠仓库里的 `node_modules` 通过，装到用户机器上却起不来；"跨重启"测试其实在同一进程中模拟。上百条单元测试全绿，而用户打开应用看到的是空白的助手回复。

因此本章的核心要求【硬性】：**每道门禁都必须在它声称验证的那个边界上运行。**

## 2. 门禁清单【硬性】

| 门禁 | 验证什么 | 必须在哪里运行 | 何时 |
| --- | --- | --- | --- |
| 类型检查 + lint + 依赖方向检查 + 许可证检查 | 代码规范、包依赖不越层、无非宽松许可依赖 | CI | 每次提交 |
| 单元测试 | 纯逻辑（状态机、编解码、SQL 装载、提示词组装、事件 reduce） | CI | 每次提交 |
| 契约测试 | 每个 HTTP 端点的真实响应符合契约 | 真实 HTTP 服务 + 真实 SQLite 文件 | 每次提交 |
| 同步通道回放测试 | 录制的真实同步通道消息流经前端 `reduce` 后得到预期界面状态 | 真实后端录制 → 前端纯函数 | 每次提交 |
| 投影重建测试 | 删除全部投影后从会话日志重建，与增量维护结果完全一致（[10 §3.3](10-data.md#33-会话投影可重建)） | CI | 每次提交 |
| 文档并发模糊测试 | 多代理 + 模拟用户对同一文档随机提交：无丢失更新、冲突只在重叠时发生（[07 §12](07-workbook-engine.md#12-m0-技术验证spike硬性必须在-m1-开始前完成并写-adr) 并发项） | CI | 每次提交 |
| Univer 操作回放一致性测试 | 前端实例产生的 mutation 在服务端实例复现后两边快照一致 | CI；**Univer 升级时必跑** | 每次提交 + 升级 |
| 跨进程恢复测试 | 待审批、排队消息、运行中代理在**进程被强制杀死**后的恢复行为 | 两个独立进程，中间 `SIGKILL` | 每次提交 |
| 保真语料测试 | [07 §12](07-workbook-engine.md#12-m0-技术验证spike硬性必须在-m1-开始前完成并写-adr) 的语料全集 | CI（含 LibreOffice 无头打开校验） | 每次提交（表格引擎变更时全量，其他时抽样） |
| 沙箱逃逸测试 | [08 §7](08-sandbox.md#7-m0-技术验证硬性) 的用例全集 | CI | 每次提交 |
| E2E 测试 | 用户可见流程 | 真实浏览器（Playwright）+ 真实后端 + 假模型 | 每次合并到主分支 |
| 安装包自检 | 打包产物能在干净环境运行 | **仓库外**解压/安装后执行 `--self-test`，macOS 与 Windows | 每次构建安装包 |
| 性能基准 | [01 §5.1](01-product.md#51-性能推荐目标值在-m1-结束时用基准测试确认后改为硬性) 的指标 | 固定硬件 | 每周 + 发布前 |
| 真实模型评测 | 模型在真实任务上的完成质量 | 真实模型 + 隔离的数据目录 | 发布前 + 修改提示词/工具说明/技能后 |

任何门禁都不允许在测试中替换**我们自己**的代码。假模型只替代模型服务的输出。

## 3. 测试分层

### 3.1 假模型

- 基于 AI SDK 的测试模型（`ai/test` 中的 mock 语言模型）实现可编排的脚本：给定输入模式，按脚本输出文本、思考、工具调用，可注入流中断、429、超时。
- 所有运行时测试（循环、审批、派发三策略、压缩、中断恢复、多代理）使用假模型。

### 3.2 提供商回归

- 每个提供商预设录制一组真实请求/响应（带思考的多轮 + 工具调用 + 图片输入），脱敏后作为回放夹具。
- 回放测试验证：请求格式（尤其思考内容回传、缓存标记）与响应解析。
- 录制脚本可在有密钥的环境中重新录制，更新夹具需人工审查差异。

### 3.3 前端

- 组件测试：消息块、工具卡片状态、提问题型、审批条、设置表单。
- `reduce` 测试：用真实录制的同步通道消息流。
- E2E：见 §5。

## 4. 覆盖要求【推荐】

- `runtime`、`workbook`、`sandbox`、`protocol` 包：行覆盖率 ≥ 85%，状态机的每个状态转换都有测试。
- 覆盖率只作参考，不作为"完成"的证据；"完成"以 §5 的场景验收为准。

## 5. 端到端验收场景【硬性：v1 发布前全部通过】

使用假模型的 E2E 版本在 CI 中运行；使用真实模型的版本在发布前人工或半自动运行并保存记录（录屏或截图 + 同步通道消息流）。

| # | 场景 | 通过标准 |
| --- | --- | --- |
| 1 | 首次启动 → 添加 API Key → 能力探测 → 发送"你好" | 流式回复正常显示；探测结果显示；状态栏数字正确 |
| 2 | 上传 sales.xlsx，问每列含义 | 代理读取总览与样本；回复中的区域引用可点击定位 |
| 3 | 按地区汇总并画柱状图 | 新工作表 + 原生柱状图；变更摘要列出新工作表与图表；在 Excel/WPS/LibreOffice 中打开无修复提示 |
| 4 | 统一日期格式、空值标黄，代理用区域确认题型提问 | 表格高亮建议区域；用户重新选择后提交；写入只作用于确认的区域；原文件有备份；变更高亮正确 |
| 5 | 用户在代理修改期间手动编辑同一工作表 | 用户改 A 列、代理同时改 F 列都成功（区域不重叠不冲突）；用户改代理读过的区域时，代理收到"用户修改了 X"通知并只重读该区域；用户输入未被静默覆盖 |
| 6 | 审批：`confirm` 模式下写入 | 表格预览层显示拟修改内容；拒绝后文件不变且代理收到理由；批准后写入 |
| 7 | 删除文件 | `standard` 模式下需审批；批准后文件进入回收站，可恢复 |
| 8 | 运行中追加消息：分别用 steer、interrupt、queue | 三种行为符合 [04 §4](04-agent-runtime.md#4-消息派发)；派发状态显示正确；刷新页面后状态一致 |
| 9 | 待审批时强制杀死后端再启动 | 审批仍在；批准后继续执行并完成 |
| 10 | 写入工具执行中强制杀死后端再启动 | 代理显示中断；工具卡片为"未执行"或"结果不确定"；点继续后代理先重新读取再决定 |
| 11 | 流式输出中断网 10 秒再恢复 | 前端自动重连，经同步通道按游标续传，内容无丢失无重复 |
| 12 | 长对话触发自动压缩 | 压缩块出现；压缩后代理仍记得用户目标与已确认的口径 |
| 13 | 12 个文件批量整理（多代理） | 子代理并行（不超过并发上限）；子代理之间的消息在团队视图可见；用户能直接给某子代理发消息；最终汇总正确；预算不被突破 |
| 14 | 两个子代理试图写同一文件 | 后者收到 `FILE_LEASED` 并通过消息协调 |
| 15 | 截图转表格 | 生成工作簿；代理用截图对照并至少修正一次；界面变更摘要与实际一致 |
| 16 | `run_script` 批量处理 5 个文件，脚本中途抛错 | 没有任何文件被修改；错误信息指出脚本行号 |
| 17 | `run_script` 死循环 | 超时终止；应用其他功能不受影响 |
| 18 | 用备份替换文件 | 替换后内容与备份一致；替换前的文件也有备份 |
| 19 | ChatGPT 订阅登录（浏览器与设备码各一次） | 登录成功，自动生成档案，能正常对话；令牌过期后自动刷新 |
| 20 | 配置一个 MCP 服务器并调用其工具 | 审批流程正确；结果显示 |
| 21 | 保存记忆后新开会话 | 相关记忆被注入并影响行为；用户可删除 |
| 22 | 模型接口返回 401 / 429 / 上下文超限 | 分别显示正确的错误指引、重试提示、自动压缩后重试 |
| 23 | 桌面：安装 → 使用 → 自动更新到新版本 → 数据仍在 | macOS 与 Windows 各一次 |
| 24 | 打开含透视表、切片器、宏的 xlsm，修改一个单元格 | 其他对象全部保留；在 Excel 中打开正常，宏仍在 |
| 25 | 两个窗口同时打开同一会话与工作簿 | 一个窗口的编辑与代理写入在另一窗口 200 ms 内出现；两端修订号与状态一致 |

## 6. 真实模型评测

- 维护一个评测集（初始 40 个任务，覆盖 [01 §2](01-product.md#2-目标用户与典型场景) 的场景类型），每个任务包含：输入文件、用户指令、**可自动判定**的结果检查（输出文件的值/结构/对象断言）、可选的人工评分项。
- 评测在隔离的数据目录中运行，记录：是否成功、工具调用次数、token、耗时、失败原因分类。
- 至少在 3 个模型上运行（一个国际旗舰、一个国产主流、一个较小/便宜的模型）。
- 修改系统提示词、工具说明、技能后必须重跑评测并与上次结果对比；成功率下降超过 5 个百分点需要说明原因。
- 参考指标：旧项目中一次回归分析任务调用了 58 次工具，其中 55% 用于确认能力是否存在。新版同类任务的目标是 ≤ 12 次调用。

## 7. 验收记录

每个里程碑结束时在 `docs/acceptance/<里程碑>.md` 记录：执行了哪些门禁与场景、环境、结果、证据位置（CI 链接、录屏、同步通道消息流文件）、已知问题。**没有证据的项不能标记为通过。**
