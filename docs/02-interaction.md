# 02 交互设计

本文描述用户看到和操作的一切。视觉风格、组件库、动画属于【开放】；信息架构、交互流程与状态语义属于【推荐】；标【硬性】的是与数据安全或产品承诺直接相关的交互。

后补的工作台与设置草案已整理为 [16 页面设计参考](16-design-reference.md)。它提供视觉与构图参考，不是最终页面规格；不要求一比一复刻。最终设计先满足本文的实际流程与状态语义，再选择合适的视觉表达。

## 1. 设计原则

1. **同一张表，两个人在看**：用户与代理共享同一个工作簿视图。代理的每一个动作（看了哪里、打算改哪里、改了哪里）都能在表格上找到对应位置。
2. **先看见，再同意**：任何需要用户确认的写入，都先在表格上预览效果，再让用户决定。
3. **不打断正在做的事**：代理的界面切换是"建议"，用户正在编辑或查看其他内容时不强行跳转。
4. **状态来自服务端**：界面上的"执行中、排队中、已完成、中断"等状态只来自服务端事件，前端不自行推测。

## 2. 整体布局

### 2.1 桌面布局（宽度 ≥ 1280px）

```
┌──────────┬───────────────────────────────────┬────────────────────┐
│ 侧栏      │ 表格工作台                          │ 对话面板            │
│ ─ 会话    │ ┌ 文件标签页 ─────────────────────┐ │ ┌ 会话标题/模型 ──┐ │
│ ─ 文件    │ │ 工具栏 / 公式栏                  │ │ │ 消息流          │ │
│ ─ 代理团队│ │ 表格画布（代理活动叠加层）          │ │ │                 │ │
│          │ │ 工作表标签                        │ │ │                 │ │
│          │ └────────────────────────────────┘ │ ├ 待审批/提问条 ──┤ │
│ 设置入口  │ 变更导航条（本轮改动 3/17 ◀ ▶）       │ │ 输入框           │ │
└──────────┴───────────────────────────────────┴────────────────────┘
```

- 未打开任何工作簿时，对话面板居中占满主区域（"对话优先"）。
- 打开工作簿后自动切换为"表格 + 对话"分栏，分栏比例可拖动并记住。
- 用户可折叠对话面板（表格全屏）或折叠表格（对话全屏）。
- 侧栏的"代理团队"页在会话有子代理时出现。

### 2.2 窄屏布局（768–1279px）

表格与对话变为标签页切换，对话输入框在表格页底部保留一个迷你输入条。v1 最小支持宽度 1024px；768px 布局为手机端预留（P2），v1 保证不崩溃即可。

工作台各区块、密度与状态表达可参考 [16 §2–3](16-design-reference.md#3-工作台页面参考)；其中的尺寸与原始截图不固定分栏比例，也不覆盖上述窄屏交互。

手机版的表格与对话初步草稿另见 [16 §7](16-design-reference.md#7-手机页面参考p2)。P2 以进度、只读区域确认、审批与消息为核心；导航、卡片和触摸形式可按实际任务调整，不要求复刻草图，也不提前扩大 v1 支持范围。

### 2.3 工作区与会话落点

- 侧栏的聊天页直接按 **工作区（项目）→ 会话** 两级组织，展示全部已登记的工作区，会话缩进在所属工作区之下；不再通过顶部选择器隐藏其他工作区的聊天。点击任一聊天自动进入它的真实工作区。
- 工作区分组可折叠，折叠只改变展示，不切换工作区或创建会话；本机记住折叠偏好。默认显示最近 5 条，当前选中历史不在这 5 条时额外保留；“展开显示/收起显示”控制更多历史。搜索时自动展开命中分组并显示全部匹配标题，清空搜索恢复原展示偏好。
- 聊天页数量来自全部会话，搜索覆盖当前可见信息架构下各工作区的会话标题，匹配结果仍保留父级工作区归属。加载完整游标分页后再分组，不能因全局前 50 条都是别的工作区而漏掉历史；不增加全文内容搜索。
- 工作区标题旁提供在**该分组**新建会话的入口，菜单提供打开工作区、查看其文件和管理工作区。顶部新建与快捷键沿用当前活动会话工作区；点击其他工作区的分组新建则明确绑定该工作区。
- 添加文件夹入口始终存在；空工作区也保留分组与新建入口。文件页只显示当前工作区文件，保留工作区选择器（路径、默认标记和会话数）；从分组的“查看文件”进入时先切换真实工作区。
- **每条会话必须绑定已登记的工作区【硬性】**。新建会话沿用当前工作区；没有有效选择时使用首选工作区，最终由后端默认工作区承接。默认工作区位于 `<数据目录>/workspace/`，不需要用户先准备文件夹或配置模型。
- 自动进入应用恢复本机上次选择的有效工作区与会话；该会话已被删除时打开同区最近会话。工作区登记失效时回退默认工作区。切换工作区恢复该区上次打开的有效会话，其次最近会话。
- 空工作区、首次进入或删除本区最后一条会话后，自动建立或复用一条**真实持久化的空白会话**，保持可输入的新对话。显式“新建会话”（侧栏/快捷键/桌面菜单）始终创建另一条；自动落点不得持续堆积空会话。
- 空白复用由服务端判断：标题未设置、只有会话创建与主代理创建记录、仅一个空闲主代理。改名、改权限/模型、发送过消息或发生执行记录后不再复用；复用不改写旧日志、权限或冻结的系统提示词。
- 本地只保存工作区/会话 ID 的导航偏好与按会话的输入草稿；真实归属以会话详情为准。较早的异步返回不得覆盖用户后来选择的工作区或会话。
- 跨工作区切换关闭工作簿并清除选区/钉住的区域上下文和旧文件列表。跨会话清除未发送的图片附件、文件引用卡片与待追加引用；文字草稿仍按各自会话保存。上传和文件操作继续使用当前会话的工作区。
- 登记文件夹后进入该工作区。桌面使用系统目录选择器，也可填写绝对路径；本机 Web 填写绝对路径。登记失败保留输入并显示后端原因。登记成功而打开失败时重试打开同一工作区，不重复登记。

决定和边界见 [ADR 0015](decisions/0015-workspace-session-landing.md)。

## 3. 对话面板

### 3.1 消息流中的块

一条助手消息由若干块组成，按时间顺序排列：

| 块 | 显示 | 交互 |
| --- | --- | --- |
| 思考 | 默认折叠，显示"思考了 N 秒" | 展开查看 |
| 正文 | Markdown，表格、代码高亮 | 单元格/区域引用（如 `Sheet1!B2:D9`）可点击定位并高亮 |
| 工具调用卡片 | 工具名的中文标签、参数摘要、状态（等待参数/执行中/成功/失败/未执行/结果不确定） | 展开查看完整参数与结果；表格工具卡片提供"在表格中查看" |
| 待办清单 | 步骤与完成状态 | 实时更新 |
| 子代理卡片 | 子代理名、任务、状态、最近动作 | 点击进入该代理的视图 |
| 审批/提问结果 | 用户做了什么决定 | — |
| 重试提示 | 模型接口重试中（第 2/5 次，3 秒后） | — |
| 错误指引 | 错误类别、原因、可执行的下一步（如"去设置检查密钥"、"换一个模型重试"） | 按钮直达 |
| 变更摘要 | 本轮实际修改的文件、工作表、单元格数、新增对象 | 点击逐项定位 |
| 文件交付 | 代理提供的下载文件 | 下载、在工作台打开 |
| 用量 | 本轮输入/输出/缓存 token | 悬停查看 |

**工具调用状态的判定【硬性】**：

- 参数仍在流式生成：等待参数。
- 模型流中断导致调用从未进入执行：**未执行**（灰色），不是失败。
- 进入执行后进程重启、结果未知：**结果不确定**（黄色），提示"请检查文件后再继续"。
- 执行完成：成功或失败，以工具返回为准。

#### 流式滚动与历史阅读

2026-10-01 用户要求修复流式对话中无法向上查阅历史的问题，并区分自动跟随与自由滚动（决策见 [ADR 0017](decisions/0017-chat-scroll-ownership.md)）。

- 对话视口有“跟随最新”和“自由阅读”两种状态。首次打开默认跟随；仅滚动对话视口，不滚动整个页面。
- 用户向上滚轮/触摸滑动、使用向上导航键、拖动滚动条、选择消息文字或展开历史详情时，立即释放跟随并取消尚未执行的自动滚动。不阻止浏览器的原生滚动。
- 自由阅读时，新增正文/思考、工具状态变化、流式内容落定、重连回放、输入草稿变化、面板尺寸变化都不主动恢复跟随。以可见消息及其视口偏移保持阅读位置；内容删除后最多校正到有效滚动范围。
- 用户主动向下滚到距底部 24px 以内、在历史视口按 `End`，或点击浮动的“回到最新”（生成中为“回到最新并跟随生成”），恢复跟随。`End` 直接回到最新并跟随，避免原生动画只到达按键时的旧底部。内容缩短或视口增高导致底部自动接近，不算主动恢复。
- 发送、排队、停止或生成结束本身不抢占自由阅读位置。恢复跟随是独立的用户动作。
- 跟随时，正文/展开的思考增高、图片或 Markdown 后续布局、输入区增高及面板缩放都使最新内容保持可见；按帧合并更新，不积累平滑滚动动画。
- 工具详情的内部滚动与外层对话隔离；键盘输入框与候选控件不被对话导航键接管。对话历史视口可通过键盘聚焦。
- 同一浏览器中按会话与代理保存最近 30 个视图的阅读位置；切换后首次出现的新视图跟随最新，返回旧视图或重新显示隐藏面板恢复该视图的状态。此偏好只在当前页面内存中，不写入会话日志；刷新后默认跟随最新。

### 3.2 用户消息

- 显示附件缩略图、引用的文件与区域徽标。
- 运行中追加的消息显示派发状态：`引导 · 等待下一步` / `打断 · 正在停止当前任务` / `排队 · 前面还有 2 条` / `已生效` / `已撤回` / `失败`。
- 尚未生效的引导/排队消息显示虚线浅色气泡和灰色时钟，点击正文可编辑；不显示气泡下方的紫色派发说明，待送达状态通过辅助技术描述提供；下方提供「打断并发送」和「删除消息」。编辑和打断通过原子替换实现；已生效则拒绝操作并保留真实状态。删除撤回待处理派发并从聊天隐藏，历史日志仍保留。网络提交失败仍显示错误并保留输入草稿，不伪装成已受理气泡。

### 3.3 输入框

- 多行输入，`Enter` 发送、`Shift+Enter` 换行（可设置）。
- **上下文徽标区**（输入框上方）：
  - 当前选区徽标：`📌 销售.xlsx · Sheet1!B2:F40`，用户在表格中改变选区时自动更新；可移除；可"钉住"（不再随选区变化）。
  - `@` 引用的文件、区域、技能徽标。
  - 图片附件缩略图与普通文件引用卡片，显示上传状态，可在发送前移除。
- `@` 弹出候选：文件（工作区内模糊搜索）、区域（当前打开工作簿的工作表与已命名区域）、技能。
- `/` 弹出命令：内置命令 + 可由用户调用的技能。
- 输入框使用单个蓝色圆形操作键：有可发送草稿时显示向上箭头；运行中且无草稿时显示实心方块（暂停当前任务）。Enter 和点击箭头都遵循设置中心的默认派发策略；输入框不提供策略分拆按钮。暂停保留队列，仍通过「继续发送」恢复。
- 输入框旁的「添加文件」支持任意文件，也可粘贴或拖入。PNG/JPEG/GIF/WebP 图片作为图片附件；其他文件上传到当前工作区，在发送消息时附上 `@路径` 引用。上传中或失败时阻止发送，移除卡片只取消消息引用，不删除已经上传的工作区文件。同名上传返回冲突，不凭文件名推断为同一个文件；工作区已有文件通过 `@` 候选直接引用。
- 输入框底部提供模型名、当前思考等级与向下箭头组成的组合入口；模型菜单使用大圆角列表和右侧选中勾，思考等级子页使用六个离散停点的滑条（无、低、中、高、极高、最高），独立重置按钮恢复「默认」。不增加语音功能。思考等级直接切换当前代理使用的模型档案的默认思考强度（09 §3），保存后在后续模型请求中生效。与设置中心编辑同一字段；共用该档案的代理使用同一默认值，具体等级支持范围由提供商决定，未配置模型时禁用。
- 输入草稿按会话保存在本地，刷新不丢。

### 3.4 待处理交互条

待审批、待回答的问题固定显示在输入框上方（而不是只在消息流里），同一时间可能有多个（来自不同代理），按时间排列，每条标明来自哪个代理。

## 4. 代理与表格的联动

这是产品差异化的核心。

### 4.1 区域引用可点击

对话中所有出现的区域引用（正文、工具卡片、提问）都是可点击的：

- 悬停：表格上以虚线框预览该区域（若该文件已打开）。
- 点击：打开对应文件、切换工作表、滚动到区域并高亮 2 秒。
- 引用带修订号时，如果文件已变化，悬停提示"该引用基于旧修订，内容可能已变"。
- 当前文档或引擎不能定位该区域时（例如 CSV 只有 2 行而引用到第 6 行），保留工作簿与页面，提示区域无法定位；不自动扩展网格或裁剪引用。

### 4.2 代理活动叠加层

表格画布上方有一个不影响编辑的叠加层，显示代理活动：

| 状态 | 样式（示意） | 来源 |
| --- | --- | --- |
| 正在读取 | 浅蓝色虚线框，淡出 | `workbook_activity` 增量与 `presence` |
| 计划修改 | 橙色虚线框 + 角标"待确认" | `workbook_activity` 增量与 `presence`（需审批的写入、`dryRun` 预览、代理的 `present` 高亮提示） |
| 已修改 | 短时绿色边框反馈，提交时轻亮后淡出；提示卡带勾选图标、区域数与修订号 | 本轮实际提交结果（`tool.result` 的变更摘要，工作台内容由 `doc.op` 同步），不是模型自述 |
| 冲突 | 红色边框 | 写入因区域冲突被拒的区域 |
| 其他代理正在处理 | 带代理名称和颜色的细边框（类似协作编辑的光标） | `presence` |

- 叠加层可以一键隐藏。
- 2026-10-01 用户要求替换常驻绿色遮罩，按 [ADR 0019](decisions/0019-transient-change-highlights.md) 改为提交后 6 秒内的短时反馈。初始淡填充迅速退去，细边框随后淡出；减少动效时只显示细边框并按同一时间清除。
- 提示卡明确说明“刚刚修改”“高亮自动淡出”，提供可通过键盘操作的“清除高亮”。清除或开始下一轮立即移除本轮反馈；之后的新提交继续提示。提示卡主体不拦截单元格操作，只有清除按钮接收点击。
- 重复修改同一区域刷新最新提交的反馈与修订号；部分重叠区域按最新提交拆分，任何单元格仅绘制一次，不加深颜色、不把未修改空洞涂满。每项反馈的寿命绑定真实提交时间，切换工作表/主题、刷新与重连不延长寿命。
- 高亮消失不代表撤销或删除变更。完整变更记录始终可在下方导航查看并重新定位（定位反馈仍按 §4.1 保留 2 秒）。显示开关只控制视觉，不改变提交结果。
- 工作表标签上用小圆点标记该表有本轮修改。

### 4.3 提问时让用户在表格上选择【硬性：确认结果必须绑定修订号】

`ask_user` 工具（见 [06 §5](06-tools.md#5-交互工具3-个)）支持以下题型，前端需分别实现：

| 题型 | 表现 |
| --- | --- |
| 单选/多选 | 选项按钮，可附"其他"自由输入 |
| 自由文本 | 文本框 |
| **区域确认** | 代理给出建议区域（如"我识别到数据区是 A1:H240，表头在第 1 行，对吗？"）。表格自动打开并以橙色框高亮建议区域；提问卡片显示"确认此区域 / 我来重新选择 / 取消"。选择"重新选择"后，用户直接在表格上拖选，卡片实时显示新区域，点"确认"提交 |
| **区域选取** | 代理不给建议，只说明需要什么（如"请选择要汇总的列"）；可限定单个/多个区域、是否限定在某工作表 |
| **修改确认** | 代理给出拟修改内容（由 `dryRun` 生成），表格上以预览层显示修改后的值（原值可悬停查看）；卡片提供"应用 / 修改后再应用（回到对话说明）/ 取消" |

提交的答案包含：文件、工作表、区域、该文件在用户确认时的修订号。代理拿到答案后如果修订号已变化，写入会因区域冲突被拒，需要重新读取——这防止"用户确认的是旧内容"。

### 4.4 写入审批在表格上预览

权限模式要求审批的写入（见 [04 §5](04-agent-runtime.md#5-权限与审批)）：

1. 审批请求到达时，若目标工作簿已打开，表格上显示预览层（新值、新格式、新增/删除的行列、插入的图表占位框）。
2. 审批条显示：`代理想修改 销售.xlsx · Sheet1!C2:C240（238 个单元格）`，固定决策行直接显示 `批准` / `拒绝`，具名的“更多审批操作”菜单提供 `本会话同类操作自动批准` 和表格预览；另有“查看详情”展开参数。自动批准仍须显式选择才提交，打开菜单不产生决定。布局调整见 [ADR 0021](decisions/0021-editorial-interface-and-approval-actions.md)。
3. 拒绝时可附一句理由，理由会返回给代理。
4. 未打开工作簿时，只显示审批条，提供"在表格中预览"。

### 4.5 变更导航与查看原值

每轮结束（或用户随时）可以打开变更导航条：

- 列出本轮所有被修改的区域（按文件、工作表分组），`◀ ▶` 逐个跳转。
- 选中已修改单元格时，侧边小窗显示"修改前：xxx"（来自修改前备份，见 [07 §7](07-workbook-engine.md#7-修改前备份)）。
- 提供"用备份替换当前文件"入口（整文件级，不做单元格级回退），替换前二次确认。

### 4.6 从表格发起对话

- 右键菜单："问代理…"（打开输入框并附上当前选区）、"解释这个公式"、"检查这列数据"、"用这个区域画图"。快捷项清单可配置，每项本质是一段预置提示词 + 选区上下文。
- 选中单元格时，公式栏旁有一个小按钮"问代理"。

### 4.7 用户与代理同时编辑【硬性】

- 代理运行中，用户可以正常编辑表格，不加锁。用户编辑与代理写入只要区域不重叠，就互不影响、不冲突（区域级一致性模型见 [03 §6](03-architecture.md#6-一致性模型硬性)）。
- 用户的编辑随时保存，每次提交产生一个新修订号。
- 只有当代理的读集或写集与用户新修改的单元格重叠时，代理的提交才被拒绝；代理只需重读被改的单元格再写。界面在代理重读时显示提示"表格刚被你修改，代理正在重新读取"。
- 读过该区域的代理在下一步收到通知（"用户修改了 汇总!B2:B9"），而不是等到写入冲突时才发现。
- 代理写入后，若用户正在编辑的单元格被代理改了，用户未提交的输入不会被静默覆盖：弹出冲突条，显示"你的输入 / 代理的值"，让用户选择保留哪个（保留用户输入即产生一次新的用户编辑）。
- 用户自己的编辑提交（`doc.submit`）也可能被拒（例如恰好与代理刚写入的单元格重叠）：前端撤销本地变更，在该单元格显示冲突条，让用户选择保留谁的值。

### 4.8 界面跟随

- "跟随代理"开关（默认开）：代理读写某文件时，工作台自动打开该文件并滚动到活动区域。
- 以下情况不自动跳转，只在文件标签上闪烁提示：用户正在编辑单元格、用户在 5 秒内手动切换过视图、目标是另一个子代理的活动。

### 4.9 实时协作

- 代理的写入实时出现在工作台：大批量修改按分片逐步显示（带轻微动画），不打断用户当前的选区与滚动位置。
- 在线状态显示其他窗口/设备与各代理正在查看或编辑的区域：每个参与者有颜色与名称（类似协作编辑的光标）。
- 多个客户端同时打开同一会话与工作簿时，看到的修订与状态一致；每个客户端的编辑提交得到各自的确认。

## 5. 代理团队视图

当会话中存在子代理时，侧栏出现"代理团队"：

- 列表/树：每个代理的名称、颜色、角色、状态（运行中/等待消息/等待审批/已完成/已停止/出错）、当前在做什么（最近的工具调用）、消耗的 token。
- 点击代理进入**代理视图**：该代理的完整对话（与主会话同样的消息流组件），输入框直接向该代理发消息（作为用户消息进入它的收件箱）。
- **团队消息流**：代理之间的消息以"内部消息"形式显示（发件人 → 收件人，摘要），默认折叠在主会话消息流里，可在团队视图中查看全部。
- **任务板**（P1）：共享任务的列表、认领人、状态。
- 操作：暂停、继续、停止单个代理；"停止全部子代理"。

## 6. 文件面板

- 工作区文件树：上传、新建文件夹、重命名、移动（拖放）、删除（移入回收站，可恢复）。
- 文件图标区分：表格、CSV、图片、其他；代理本会话创建或修改过的文件带标记。
- **备份**分组：列出本工作区的修改前备份（原文件名、备份时间、由哪个会话产生），可打开查看、另存、替换回原文件、删除。
- 工作区切换器：顶部下拉，列出已登记的工作区；“添加文件夹”和管理入口始终可用（详见 §2.3；桌面提供系统目录选择框）。

## 7. 设置中心

分组（左侧导航 + 顶部搜索）：

| 分组 | 内容 |
| --- | --- |
| 模型 | 模型档案列表（增删改、设为默认、测试连接、能力探测结果与手动覆盖）、订阅账号（登录/退出/刷新）、按用途选模型（P1） |
| 权限 | 默认权限模式、自动批准的 MCP 工具 |
| 运行 | 单轮最大步数、运行中消息默认策略、自动压缩开关与阈值、子代理预算默认值 |
| 技能 | 内置与用户技能列表、启用/禁用、导入、查看正文 |
| 记忆与规则 | 记忆条目管理；全局规则 |
| MCP | 服务器列表、增删改、连接测试、工具列表 |
| 外观 | 主题、字号、布局偏好 |
| 数据 | 数据目录位置、打开数据目录、清理缓存 |
| 关于 | 版本、检查更新、日志目录、许可证 |

设置表单规则【推荐】：每个字段写明"改变什么、取值含义、何时生效"；数值字段带单位与范围（与服务端 schema 一致，由 schema 生成）；保存只提交修改过的字段；需要重启的项在保存前提示。

分类导航、档案卡、能力来源与权限说明可参考 [16 §4](16-design-reference.md#4-设置中心参考)。按实际字段和已交付能力组织页面，草案中的重复导航、成员管理和配置导出不直接纳入功能范围。

## 8. 首次引导

1. 欢迎页 → 选择"添加 API 密钥"或"登录 ChatGPT 订阅"。
2. 添加后自动测试连接与能力探测，显示结果（支持工具调用 ✓、视觉 ✓、思考 ✓）。
3. 提供示例工作簿（内置），引导完成一个 3 步任务：读表 → 让代理高亮并确认区域 → 修改并查看变更高亮。
4. 引导可跳过、可在设置中重新打开。

## 9. 状态与错误

| 情况 | 界面 |
| --- | --- |
| 未配置模型 | 输入框上方卡片"还没有可用的模型"，按钮直达设置；仍可浏览文件与表格 |
| 与后端断开 | 顶部细条"正在重新连接…"；恢复后通过同步通道续传 |
| 会话中断（服务重启时正在运行） | 消息流末尾"任务在服务重启时中断"，按钮"继续"（发送 `/resume` 语义的继续请求，见 [04 §8](04-agent-runtime.md#8-中断与恢复)） |
| 模型接口错误 | 错误指引块：分类（认证、额度、限流、网络、上下文超限、模型不支持某功能、服务端错误）、原始错误摘要、下一步按钮 |
| 工具失败 | 卡片显示错误码与说明；代理通常会自行处理 |
