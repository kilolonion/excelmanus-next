**这是参考草案，不是最终页面规格，也不要求一比一复刻。** 2026-09-30 将后续补入的 `stitch/` 草案整理进文档集，供工作台、对话、设置和打磨环节使用。接入决定见 [ADR 0007](decisions/0007-design-reference-integration.md)。

【硬性：沿用现有产品与安全约束】最终页面从实际功能、用户任务和真实状态出发设计。产品范围以 [01](01-product.md) 为准，交互以 [02](02-interaction.md) 为准，运行与权限以 [04](04-agent-runtime.md) 为准，数据与接口以 [10](10-data.md)、[11](11-api-contract.md) 为准。截图中的按钮、数值、英文标签和说明不会自动成为产品需求，不得通过草案绕过上述约束。

## 2. 视觉语言【开放】

### 2.1 总体方向

可借鉴「简洁编辑工作室」风格：温暖的浅色背景承载界面，白色表格与内容卡承载任务，细边框和轻阴影划分层级。表格保留密度和数值可读性，对话保留段落间距；主要操作清晰，状态色只用于有意义的提示。

原草案的 YAML、正文和 HTML 对颜色、圆角命名有不同取值。下表从正文整理出一组便于讨论的示例，不将三套值同时搬进代码；最终实现使用一套统一 token。

| 用途 | 示例色值 | 使用建议 |
| --- | --- | --- |
| 页面底色 | `#FAFAF9` | 温暖纸白 |
| 内容表面 | `#FFFFFF` | 表格、表单、卡片 |
| 次级表面 | `#F5F5F4` | 公式栏、分组背景、折叠摘要 |
| 主要文字 / 主操作 | `#1C1917` | 正文、深色发送按钮 |
| 次级文字 | `#78716C` | 时间、坐标、非关键元信息；检查实际对比度 |
| 结构边框 | `#E7E5E4` | 面板分隔、轻边框 |
| 读取与引用 | `#4F46E5` / `#EEF2FF` | 可借鉴靛蓝虚线边框，与用户选区区分 |
| 待确认与警告 | `#D97706` / `#FEF3C7` | 拟修改区域、审批提示 |
| 已提交与成功 | `#059669` / `#ECFDF5` | 实际修改高亮、成功状态 |
| 错误与冲突 | `#DC2626` / `#FEF2F2` | 失败、冲突和停止入口 |

颜色只是一种表达。读取、待确认、已修改和冲突仍需边框样式、图标或文字辅助；成功卡与单元格填充色不能代替实际状态。深色主题另行验证，不把浅色值机械反转。

### 2.2 字体与密度

- 界面与中文正文优先保证系统字体可读；草案的 Plus Jakarta Sans 可作为拉丁字形参考，不要求安装或打包该字体。中文需完整字体回退。
- 坐标、公式、模型 ID、区域徽标可用等宽字体；JetBrains Mono 是草案示例。数值使用等宽数字以利于纵向比较，不要求所有中文单元格采用等宽字体。
- 页面标题可参考 22–28px，分组标题 15–18px，正文 13–16px，元信息 11–12px；关键操作、审批理由和错误说明不缩小为装饰性小字。
- 间距可从 4 / 8 / 12 / 16 / 20 / 32px 起步。单元格直角，徽标约 4px，控件约 8px，卡片约 12–16px；按组件实际尺寸调整。
- 表格网格、行列标题、公式栏由同版本开源 Univer 的能力组织，不另写一套静态 HTML 表格去模拟产品引擎。草案的 28px 标题行、36px 公式栏只是密度示意。

### 2.3 层级与素材

基础表面尽量平坦；浮层、待处理卡或输入框可使用轻阴影，避免每个区块都提升层级。动效只帮助解释活动与变化，不影响选区、滚动或编辑；尊重减少动效偏好。

2026-10-02 的视觉打磨采用以下开放范围内的构图：温暖灰底的导航侧栏，细边框纸面式主区域；输入区、浮层与待处理交互拥有轻量层次，其余内容保持平坦。按钮和表单采用一致的高度与内边距，任务卡按对话面板实际宽度排为三列或两列；分栏中的标题、控件和输入提示随容器收紧，工作台选区以公式栏、输入上下文和状态详情表达，避免在文档头重复占位。

空白会话的任务页从顶部浏览，不自动滚到任务卡底部；出现真正消息后沿用 02 §3.1 的跟随与自由阅读。待处理区限制高度并可独立滚动，较短窗口中的审批操作固定在其底部，输入与发送保持可用。动效采用短时淡入、轻微位移、悬停和焦点反馈；减少动效偏好同时关闭位移动效。设置弹窗保留退出动画，并将焦点归还原入口。

本轮不改变 v1 最小支持宽度与 P2 范围。实际页面和门禁记录见 [2026-10-02 UI 打磨验收](acceptance/ui-polish-2026-10-02.md)。

2026-10-02 用户反馈上述第一轮仍显简陋，后续改以阅读顺序和完整交互面为主：空白会话把输入框放在标题与紧凑任务建议之间，统一面板头部与设置页正文基线，元信息退后、关键操作保留足够文字尺寸与按钮面；新增/高级表单渐进展开，审批保留单行主决策并将次级操作移至具名菜单。参考草案的构图取舍与页面证据见 [后续整体复核](acceptance/ui-editorial-2026-10-02.md)，交互调整见 [ADR 0021](decisions/0021-editorial-interface-and-approval-actions.md)。上一轮门禁通过不代表视觉反馈已被用户认可。

【硬性：沿用隐私、许可证与打包约束】产品界面资源不能照搬草案的 Google Fonts、Tailwind CDN 或远程 Logo。采用本地资源或系统字体；新增字体、图标或其他素材先核实许可和来源，并遵守既有依赖与合规门禁，不放宽策略。桌面离线可加载的资源随应用打包（13 §4.1）；浏览器加载界面不因此向第三方发送数据（01 §5.4）。

2026-10-01 按用户明确要求沿用一代品牌图标：从 `~/Desktop/excelmanus/web/public/icon.png` 提取为本地 `packages/web/public/brand-icon.png` 与 `favicon.png`，用于侧栏、连接状态页及浏览器标签图标。仅复用用户指定的品牌素材；不参考或复制旧项目实现代码。图标经 `Icon.tsx` 的 `BrandMark` 统一使用，随 Web 构建产物打包。来源与检查记录见 [品牌图标接入验收](acceptance/brand-logo-2026-10-01.md)。

2026-10-02 进一步按用户要求复用一代 `web/public/providers/` 中 22 个 SVG 素材，仅新增缺失的 Ollama 与正确的 xAI 标识；一代 `x.svg` 的内嵌标题为 X.Org，不能用于 xAI。补齐素材来自 MIT 许可的 Lobe Icons，许可文本和源文件 SHA-256 随资源存档。提供商品牌图标仍经 `Icon.tsx`，与操作、状态图标分开；后者保留原有语义。具体入口、主题与页面证据见 [提供商 Logo 验收](acceptance/provider-logos-2026-10-02.md)。

## 3. 工作台页面参考

### 3.1 功能决定布局

按照 02 §2：未打开工作簿时以对话为主；打开后呈现表格与对话。草案可帮助安排文件标题、公式栏、消息流、输入框和状态信息，但截图的 256px 侧栏、62%/38% 分栏及顶部横栏都不是固定规格。

【开放】优先给表格足够的可操作空间，再给对话、审批和输入足够的可读空间。宽屏可参考 380–440px 的对话初始宽度，但应结合视口、侧栏和真实内容调整，并沿用 02 的可拖动、折叠与比例记忆。避免文件名、权限、模型与修订号在多个栏位重复占位。

窄屏继续使用 02 §2.2 的表格/对话标签切换与迷你输入条。草案中 360px 抽屉、48px 微栏、手机底部抽屉不覆盖现有交互；若未来选用，需先评估任务可完成性与对应阶段范围。

### 3.2 可借鉴的组件

| 组件 | 草案价值 | 最终设计依据 |
| --- | --- | --- |
| 工作区与导航 | 低噪声侧栏、明确当前所在位置 | 聊天页按“工作区 → 会话”分组、缩进、折叠与展开更多；文件页为当前工作区；真实计数、空白落点、分组新建与登记文件夹按 02 §2.3；有子代理时出现团队入口（02 §5–6） |
| 文件与工作表标签 | 文件名、当前表、修改小点容易识别 | 多工作簿标签仍为 P1；实际文档身份明确，不以示例文件名定位（01 §3.2、附录 C P-10） |
| 公式栏与「问代理」 | 从数据到对话的距离短 | 选区上下文、问代理按钮、右键快捷项按 02 §3.3、§4.6 |
| 区域徽标 | 等宽坐标、可点击定位、固定/移除操作 | 文件、工作表、区域和修订按真实引用；不能只显示坐标后定位到错误文件（02 §4.1） |
| 活动叠加层 | 读取虚线、待确认琥珀、已修改轻量反馈易区分 | 02 §4.2 的状态语义不变；已修改采用 ADR 0019 的短时边框、修订提示与清除入口；叠加层不拦截正常编辑 |
| 工具卡 | 标题、范围、状态、耗时分层清楚 | 主标题用工具中文 `title`；技术名、参数和结果放详情；覆盖全部真实状态（02 §3.1） |
| 区域确认卡 | 确认、重新框选、取消可就地完成 | 答案绑定确认时的修订；区域确认与写入审批是不同事项（02 §4.3–4.4） |
| 固定待处理条 | 用户不滚动历史也能发现待答问题 | 输入框上方显示真实待审批/提问，标明来源代理；同一事项的卡片与固定条共享状态（02 §3.4） |
| 变更导航 | 修改前/后对比和跳转集中 | 拟修改预览与实际变更分开；已修改只依据提交结果，备份替换需二次确认（02 §4.5） |
| 输入区 | 上方徽标、多行输入、附件与发送清楚分区 | 默认 Enter 发送、Shift+Enter 换行；运行中策略选择与独立停止按 02 §3.3、04 §4 |
| 状态信息 | 修订、备份、同步提示靠近相关内容 | 依据当前对象真实状态展示；诊断细节按需展开，不填入示例延迟和内部会话 ID |

### 3.3 状态必须对应真实来源【硬性：沿用 02、04、07、11】

| 界面信息 | 依据 | 防止误导 |
| --- | --- | --- |
| 工具执行与结果 | `tool.intent`、`tool.result`，参数流仅用于临时展示 | 等待参数、执行中、成功、失败、未执行、结果不确定均可区分；流中断不冒充已执行 |
| 待读/拟修改区域 | `workbook_activity` 增量、`presence`、相关预览 | 橙色预览不能表示文档已经修改 |
| 工作台已应用修订 | 文档快照与按序应用的 `doc.op` | 不预报下一修订；各工作簿自己的 `rev` 不能当成会话游标 `seq` |
| 本轮实际变更 | 文档日志、`doc.op`、`change.summary` | 数量和区域不从模型正文或草案数字推测 |
| 已备份 | 修改前备份的真实完成结果 | 不将待执行备份、增量操作日志称为已创建备份 |
| 已保存 | 文档日志提交与异步 xlsx 检查点各自状态（07 §5） | 数据已提交与 xlsx 已写回要按真实阶段表达；不能仅凭 WebSocket 连通宣称文件已保存 |
| 派发 / 审批 / 提问 | `dispatch.updated`、审批与提问记录及其投影 | 点击按钮后的等待状态与服务端已确认状态分开，重复入口不会重复产生决定 |
| 上下文占用与用量 | `usage.updated` 等契约数据 | 未知值不填造；思考耗时不是工具耗时，能力探测延迟不是模型 SLA |

读取过 rev 57 的结果可以保留在历史里；若工作台已到 rev 58，应清楚表达引用过时，重新检查冲突。草案中的「rev 58 预备就绪」和已完成绿色卡不得在写入前用作成功反馈。

思考块沿用 02 §3.1 与 04 §10，仅展示模型实际提供、产品允许展示的内容；不能照抄示例的推演文本，也不要求提供商公开完整内部推理。停止沿用既有机制，不承诺强制撤销已提交修改。

## 4. 设置中心参考

### 4.1 导航与内容

参考草案的「分类导航 + 内容区 + 搜索」层级，分类仍使用 02 §7 的模型、权限、运行、技能、记忆与规则、MCP、外观、数据、关于。是否保留全局侧栏、如何呈现返回工作台、卡片还是表单，由实际内容和可用宽度决定；不照搬双重导航与重复搜索框。

M1 先支持已经定义且可工作的基础设置；M2/M3/M4/M5 随能力完善相应内容；M6a 集中统一工作台、对话、侧栏和设置中心的布局、视觉、搜索与反馈，M6b 完成首次引导等发布前打磨。未交付入口不伪装成可操作功能，布局也不为截图中的空位制造开关。

### 4.2 模型档案与能力

- 可用卡片或列表呈现档案名称、提供商、模型 ID、默认标记、连接状态和编辑入口；高级参数折叠，字段与范围以 09 §3 和 protocol 为准。
- 「测试连接」「能力探测」「刷新模型目录」「拉取远端模型列表」按 09 分别提供，结果不可互相替代；草案「测速」不定义独立性能基准能力。
- 工具调用、视觉、思考的结果显示支持/不支持/未知，并呈现 `catalog` / `probe` / `manual` 来源与时间；探测失败不等于已证实不支持，手动覆盖与旧结果须可辨。
- 按用途分配属于 P1。主对话、子代理默认、压缩摘要等按 09 的实际档案选择，不从截图推定固定模型组合、价格或更便宜的默认子代理。
- 连接和探测状态取自真实请求；模型窗口、输出上限、价格和账号可用模型来自当前目录、发现结果或用户覆盖，截图中的旧型号、延迟、配额、有效期均为示例。
- 密钥只展示读取接口的掩码，不显示密文、不获取明文供前端遮盖；未修改时不回传（10 §4）。

### 4.3 权限、订阅和数据

权限卡可以借鉴三档并列形式，但说明严格对应 04 §5：`confirm` 的写入需审批，`standard` 常规写入自动、删除与外部调用需审批（自动批准名单除外），`auto` 仍受安全边界与修改前备份约束。设置的是全局默认，会话可覆盖；子代理不超过父代理。默认模式仍保留附录 C P-2 的待决状态，不因截图选中了 `standard` 而关闭问题。

订阅区在 M5 按 09 §4 呈现浏览器授权、设备码、登录状态、刷新失败和退出；可用模型以账号发现为准，并按原要求说明非公开接口可能变化。AES-256-GCM 存储与桌面 `safeStorage` 保护主密钥按 10 §4 表达，不把整个数据库称为已加密，不把所有凭据都说成直接存进 Keychain。

数据目录显示实际运行位置（桌面 `userData` / Web 数据目录），工作区备份位置单独说明；不固定为截图路径、数据库大小和应用版本。数据与关于的入口遵循 02 §7、10、13。「导出配置」尚无字段范围与导入语义，见附录 C P-11；诊断包导出继续按现有契约实现。

设置表单沿用「改变什么、取值含义、何时生效」说明、数值单位与范围、仅提交修改字段、重启提示。测试失败、保存中、保存失败、凭据未配置都要有可理解的反馈。

## 7. 手机页面参考（P2）

### 7.1 范围与用户任务

**手机草稿同样只是初步参考，不要求一比一复刻。** 最终设计围绕 [13 §5](13-desktop-mobile.md#5-手机端预留p2) 已定义的任务：查看进度、审批、回答问题、在只读表格上确认区域、发送消息和查看变更摘要。复杂表格编辑留在电脑上；草案的公式栏、加号和「应用该项」不扩大这个范围。

v1 继续按 02 §2.2 保证已有窄屏降级，手机完整流程属于 P2。手机连接由 13 的配对与设备授权建立，沿用真实 REST + 同步通道；不能因为截图显示「Sync 18ms」而省略配对、重连或设备吊销处理。导航、底部标签或抽屉的具体形式保持【开放】，不照搬桌面的固定分栏或本草案的五个导航项。

### 7.2 页面组织与可借鉴组件

| 草案区块 | 参考价值 | 按实际功能设计 |
| --- | --- | --- |
| 顶部文件入口与同步状态 | 明确正在查看哪个工作簿及连接情况 | 长文件名可缩略但能点击查看完整名称；状态源与修订沿用 §3.3，头像不代表新增账号体系 |
| 对话 / 表格切换 | 用单一主视图解决小屏空间不足 | 当前文件、工作表、区域上下文可辨；按实际内容选择一套主导航，避免顶部标签、底部标签、浮动返回三处重复 |
| 模型与上下文条 | 提示本轮模型和上下文占用 | 次要信息可收起，优先保证消息、待处理操作与输入可见；数据来自实际档案和用量 |
| 表格浏览与公式查看 | 只读检查原值、引用与建议范围 | 横向滚动、区域定位、工作表切换可以借鉴；公式查看不意味着手机可改公式或新增工作表 |
| 修改前后预览卡 | 不依赖悬停就能比较原值与建议 | 卡片标明文件、表、区域与预览所基于的修订；拟修改与实际已修改分开，内容过长可展开 |
| 范围确认卡 | 确认 / 查看表格 / 重新选区就近操作 | 在只读表格中查看或选择区域，再返回原问题提交；确认绑定修订，不代替写入审批 |
| 固定审批条 | 长消息流中也能找到需要处理的事项 | 按真实待处理记录显示来源代理、范围、批准和拒绝；长范围和理由可展开，多个事项可逐一处理 |
| 输入、引用徽标与策略 | 触摸设备上继续发送指令 | 保留可移除/固定的引用、派发选择和运行中的独立停止；附件按已定义能力，麦克风待决 |
| 团队、审批、设置入口 | 次要任务可集中访问 | 团队在存在子代理时显示；审批与变更可分组但各自状态明确；设置不增加手机专属默认值 |

【开放】切换视图时可保留对话滚动位置、表格查看位置和未提交的区域选择，帮助用户往返核对。具体保存机制由实现决定；位置与草稿是界面偏好，审批决定、写入结果与修订仍来自服务端，不由本地缓存确认。

### 7.3 触摸、键盘与连接复核目标【推荐】

- 触摸可完成区域定位、只读框选、工作表切换、查看原值和回答问题；不以悬停或精细鼠标拖动作为唯一方式。选区手势和表格滚动应可区分，提供明确取消与返回入口。
- 固定输入区、审批条和底部导航为软键盘及安全区域让位；键盘展开、横竖屏切换和浏览器工具栏变化时，不遮住发送、拒绝、停止或正在填写的答案。草案的大块底部留白不是目标布局。
- 可参考约 44px 的触摸操作区域，并保证图标名称、可见焦点、放大后的可读性。草案 HTML 的 `user-scalable=no` 与 `maximum-scale=1.0` 不作为实现要求，不禁用用户页面缩放；应用语言沿用简体中文。
- 手机读取旧修订后进行确认，应按既有规则检查修订与冲突，不把读取 rev 57、表格 rev 58 的混合展示当成同一份当前数据。选择范围与写入审批保持不同决定，提交后等待服务端确认。
- 切换后台或断网后显示重连状态，按主题游标续传，清除过期活动提示；连接恢复后重新核对待处理事项与文档修订。重复点击沿用幂等机制，不在本地先标为已批准、已修改，也不增加离线自动执行承诺。
- 运行中手机仍须可停止任务；草案对话页只有引导与发送，没有完整展示停止操作，最终流程按 02 §3.3、04 §4 补齐。

这些是 P2 页面复核目标，尚无实机验收证据；不因此改变 v1 最小支持宽度或阶段完成状态。

### 7.4 手机草案差异处理

| 草案内容 | 处理方式 | 依据 / 待决事项 |
| --- | --- | --- |
| 表格页内容却选中顶部「对话」标签 | 当前视图与导航选中态一致 | 截图不能定义互相矛盾的状态 |
| 顶部切换 + 五项底部导航 + 浮动「切回对话」 | 由实际任务选择与合并，不固定三套入口 | 构图【开放】，避免重复占用小屏 |

| 头像、加号、公式栏与表格静态 HTML | 按已有功能组织；不隐含多人账号、编辑或另一套表格引擎 | 01、07、13；只读浏览也使用真实文档数据 |

### 7.5 P2 验收使用方式

手机阶段启动时，将下列流程纳入该阶段记录（可复用 14 的相关场景），使用真实手机浏览器/PWA、真实 HTTP/WebSocket/SQLite；假模型只替代模型输出。草案截图和桌面浏览器缩小视口都不代替实机证据。

| 流程 | 页面复核与证据 |
| --- | --- |
| 电脑配对 → 手机查看同一会话与工作簿 | 授权成功、设备状态、文件身份、文档修订一致；记录平台与浏览器版本 |
| 区域引用 → 表格定位 → 重新框选 → 返回回答 | 触摸可完成、上下文没有指错文件、确认绑定修订；结合 14 场景 4、25 |
| 查看待审批 → 批准或附理由拒绝 | 长范围可读、固定操作不遮挡、决定与实际执行一致；结合场景 6、9 |
| 发送 / 派发 / 停止 → 查看团队与变更 | 软键盘、横竖屏、安全区域下可操作；未将变更数误作审批数；结合场景 8、13 |
| 切后台 / 断网 → 恢复 → 电脑同步修改 | 续传无重复、过时范围提示、待处理状态正确；结合场景 11、25 |
| 未配对 / 设备被吊销 / 服务不可达 | 可理解的连接与授权反馈，不显示伪造同步或执行成功 |

导航结构、批次逐项处理和语音输入的最终方案仍按已定义需求及附录 C 决定。接入记录见 [手机参考文档补充记录](acceptance/mobile-design-reference-integration.md)。
