# ADR 0025：前端换成一代界面，跑在二代后端上

- 日期：2026-10-11
- 状态：已采用

## 背景

二代前端（2026-10-10 重构）在操作上有不少适配和视觉问题，一代 ExcelManus（`~/Desktop/excelmanus/web`，Next.js）的界面打磨得更好，但一代后端和内核不符合二代的核心约定（会话日志为唯一事实源、活文档、区域级冲突）。

## 决定

`packages/web` 整体换成一代的视觉与操作，数据流用二代：

- 栈仍是 Vite 7 + React 19 + Tailwind 4 + zustand + radix-ui；`next/*` 换成 `React.lazy` 等原生写法，不留兼容层或旧接口垫片，二代旧 web 直接删除。
- 界面状态只来自服务端记录和事件：`lib/session/reducer.ts` 由会话日志还原时间线，`stores/*` 只经契约客户端发请求。
- 两代重叠但语义不同的功能按二代语义重做，例如「从这条消息重新开始」是追加 `history.rewound` 记录，只截断对话、不回滚文件。
- 一代有、二代后端没有的功能不造假、不留空壳入口，记在 backlog「一代功能待后端适配」。
- 审批和提问内联在工具卡上：批准只放行这一次；勾选「本会话自动批准同类操作」提交 `remember=true`；「允许全部」先把会话切到自动模式再批准；拒绝可附理由。工具步骤改为扁平的 `.em-step-*` 样式。这取代 ADR 0021 中审批「更多审批操作」菜单的布局，审批语义不变。

协议随之升到 v3（rewind、present 载荷、`tool_args` 增量、会话 activity、工作区排序），见 [11 §1](../11-api-contract.md)。

## 后果

- 一代的部分功能暂时没有（见 backlog），需要逐项补后端。
- 一代代码的 Biome 诊断多（a11y、依赖数组等），`biome.json` 对 `packages/web` 把这几类降为警告，其余规则照旧报错。
- 「允许全部」影响整个会话，比「同类操作自动批准」范围大，保留它是沿用一代行为。
