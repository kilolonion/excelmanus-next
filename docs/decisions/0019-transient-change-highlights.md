# ADR 0019：短时改动高亮与最新提交归属

- 日期：2026-10-01
- 状态：采纳（用户要求修复常驻绿色遮罩、无法消除与重复修改叠色）

## 背景

02 §4.2 原推荐“已修改”保持到已查看或下一轮。工作台按历史区域逐个填充，部分交叠会叠色；相同区域去重后的字符串不变，也无法强调再次修改。常驻底色容易被误认为单元格格式或选区，“已查看”没有明确告知清除作用。

## 选项

1. 保持常驻，增加透明度与图例：仍遮挡数据，重复修改反馈弱。
2. 所有修改到达后重放本轮全部高亮：无关区域反复闪烁，历史回放也会成为新活动。
3. 按每次真实提交时间提供短时反馈，区域交叠归最新提交：可区分新旧改动，自动清除，历史保持可查。

## 决定

采用选项 3，交互以 02 §4.2 为准。绿色保留“实际已提交”的含义，但填充在最初 650ms 内退去，只保留细边框；末尾 900ms 淡出，总寿命 6 秒。反馈卡以文字、勾选、区域数和修订号解释状态，倒计时细线表达短暂性，清除按钮立即移除反馈。减少动效偏好禁用淡填充、过渡和进度动画，但保留文字、细边框、按钮和自动清除。

客户端使用会话记录的已有 `createdAt`（reducer 的 `at`）绑定寿命，不新增服务端状态或日志。没有时间戳的历史仍可导航，但不播放新改动反馈。复用 core 的区域差集，新提交拥有交叠部分、旧提交保留未被覆盖部分，不枚举大型区域的每个单元格、不使用包围盒填满空洞。仅使用 Univer 公开 facade 高亮与释放接口；稳定阶段不持续重绘，动画及退出阶段按有限节奏刷新。工作表/主题/显示开关变化清理旧图形、按剩余时间重建。

## 后果与验收

用户需要通过底部变更导航查看超过 6 秒的修改，不再靠常驻绿色填充回忆；清除只影响视觉反馈，不清空记录或撤销写入。服务器提交时间与浏览器共用本机时钟（当前 v1 本机 Web/桌面范围），不在这里定义远程设备时钟同步。每次提交窗口独立，不因重复写入而无限保留旧区域。

满足同一组验收标准：实际修改有可定位的视觉反馈；拟修改与已修改可区分；不抢占选区或滚动；叠加层可关闭；修改记录仍可审阅。额外验证重复/部分重叠不叠色与不虚增修改区域、自动/主动清除、清除后新修改、回放不重启寿命、深色/减少动效/1024px 与键盘操作。证据见 [专项验收](../acceptance/change-highlights-2026-10-01.md)。
