# ADR 0018：工作簿观察与派生 mutation 边界

- 日期：2026-10-01
- 状态：已决定（用户要求续修格式修复时的重复冲突）

## 背景

用户提供“填充内容/样式 → 截图 → 合计行改格式冲突 → 局部重读仍冲突 → 显式 baseRev 仍冲突”的调用链。只读检查该文档的修订元数据，确认修订 3 为客户端回传的 `user` 修订：包含无用户命令 `trigger` 的公式状态、计算值和公式索引更新。其中空公式矩阵被当成整表写集，稀疏值矩阵又被扩大为包围矩形。

截图虽带修订号，却未记入读集，持久读集也未识别截图结果。冲突覆盖仅认可单一重读矩形，多个区域的并集无法覆盖旧的大区域。原数字格式在常规引擎/渲染路径可以生效，问题不能靠反复传同一操作或强行放宽冲突保护解决。

## 选项

1. 让模型总是传当前 `baseRev`，或忽略引擎/格式类冲突。
2. 每次失败要求整表重读，只调整提示词。
3. 修正用户提交与派生数据边界、观察记录、稀疏写集和重读覆盖；保留真实用户修改的保护。

## 决定

采用选项 3。`core` 提供中立的 mutation 来源判定，前端和文档 actor 共用：`formula.mutation.*` 是内部状态；无有效 `params.trigger` 的 `sheet.mutation.set-range-values` 是本地公式派生事件。工作台不发送它们，服务端以 `UNSUPPORTED_FEATURE` 拒绝客户端提交，整批不执行。用户命令产生的值/公式/样式 mutation 保留 Univer 的 `trigger`，仍按同一文档路径提交；内部回滚不受该客户端规则限制。

截图成功后，按实际渲染区域和截图快照修订记入读集；结果丢失、渲染失败、被裁掉的区域不能作为观察证据。持久读集识别 `workbook_render` 的实际 `range` 和 `docRevs`。

稀疏矩阵按实际坐标生成写集，合并同行连续列和相邻行相同列段；显式空矩阵没有写集，缺失/无法推导仍保守处理。冲突判定用精确重读区域的并集扣除已确认部分，剩余格才报告冲突；粗粒度条目、被删区域和未读空洞不能解除保护。`baseRev` 不清空读集，不能用于绕过未重读的依赖。

## 后果与同组验收标准

消除本地公式重算回声产生的虚假用户修订，不改写已有历史修订，也不降低真实用户编辑的冲突保护。旧客户端漏过派生事件时会被服务端拒绝，需刷新加载新前端。手写低层 `doc.submit` 应保留真实用户命令的 `trigger`；本仓库真实 WS 测试已改用与 Univer 捕获一致的参数。

真实 HTTP/WS/SQLite 回归覆盖派生提交拒绝、截图观察、实际用户冲突、合计行重读后格式修复及 xlsx 检查点。真实 Univer 事件验证用户值/公式/样式不会被误滤，另验证分块重读的并集、空洞保护及截图读集重建。截图 WS 客户端只验证布局/协议，不据此宣称完成浏览器 canvas 像素验收。证据见 [验收记录](../acceptance/workbook-observation-conflicts.md)。
