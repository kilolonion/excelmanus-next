# ADR 0020：输入框思考等级与文件引用

- 日期：2026-10-02
- 状态：已采用

## 背景

用户要求在聊天输入框旁直接切换思考等级，并把添加图片入口扩展为任意文件引用。09 §3 已定义模型档案的 reasoning 字段；11 §4 规定图片进入内容寻址附件，其他文件上传到工作区并通过路径引用。旧输入框只允许选择图片，普通文件上传时仅凭同名就引用既有文件，不能确定引用的是用户选择的内容。

## 选项

1. 只保留设置中心编辑等级，输入框继续只选图片。
2. 新增每条消息的等级覆盖与通用二进制附件协议。
3. 输入框直接编辑当前模型档案；复用现有图片附件和工作区上传契约，以可移除卡片承载待发送的文件引用。

## 决定

采用选项 3。用户已明确选择聊天输入框入口。等级使用 protocol 的统一取值，PATCH 当前代理对应的模型档案；不扩展日志、消息与模型网关契约。普通文件上传到发起操作时的工作区，发送时把真实返回路径作为独立的 @路径 行加入消息。所有选中文件先登记上传中状态，上传失败可见并阻止发送；同名上传沿用 HTTP 409，已有文件通过 @候选引用，不凭文件名认定身份。

这是对 02 §3.3 原来“拖入工作区中已有文件直接引用”的推荐行为的收窄：浏览器 File 不提供可靠的工作区路径身份。同名自动引用可能让代理使用错误内容，显式 @引用满足同一用户意图与数据安全标准。

### 2026-10-02 后续调整：等级文案与最高档

用户追加要求：「提供商默认」改为「默认」，「不思考」改为「无」，保留其他等级并新增「最高」。增加协议取值 max，聊天和设置中心都从 protocol 枚举读取选项。锁定 SDK 的统一 reasoning 尚无 max，因此由 models 适配层经官方 providerOptions 传递，不通过类型断言把未知档位塞进统一 reasoning，也不映射成 xhigh。OpenAI/ChatGPT、Anthropic 与 OpenAI 兼容适配器传递原生 max；其余适配器返回明确的 invalid_request。后果是具体模型可能拒绝 max，但不会静默降级；以真实 SDK 请求体和 HTTP/WS/SQLite 浏览器流程验证同一保存与生效标准。证据见 [后续验收](../acceptance/reasoning-levels-2026-10-02.md)。

随后用户要求移除 minimal 的默认出现。聊天和设置共用从协议枚举派生、排除 minimal 的七个选项。保留协议取值以兼容已有档案；旧值只在控件当前值显示为「最少（已保存）」，不作为菜单选项，不自动替用户改写。此收窄不推断型号支持列表，也不以模型名称猜测能力。

## 后果与验收

- 同一模型档案被多个代理使用时，切换等级影响后续使用该档案的请求；提示说明保存范围，设置中心与刷新读回同一值。
- 图片沿用视觉能力控制、最多 8 张和单张 10 MiB 限制；普通文件沿用工作区单文件 200 MiB 限制。
- 移除卡片只取消待发送引用，不删除工作区文件；会话切换清空未发送卡片，迟到上传结果不进入新会话。
- 验收使用真实浏览器、HTTP、WebSocket 与 SQLite，假模型仅替代模型服务输出，检查等级持久化和进入网关、任意文件多选与路径发送、图片送达、冲突不覆盖、失败提示、会话切换与窄屏布局。结果见专项验收记录。
