# ADR 0021：工作室界面构图与审批次级操作

- 日期：2026-10-02
- 状态：已采用；审批布局部分被 [ADR 0025](0025-gen1-frontend-on-gen2-backend.md) 取代（审批改为内联在工具卡上）

## 背景

用户连续反馈当前界面简陋、缺少美感。既有视觉修整把控件做成了大量等权卡片，空白会话标题与输入区分离，设置页重复分区和常驻表单，窄列审批的预览、自动批准、拒绝、批准自然换行，失去清楚的决策顺序。16 §1、§2 的视觉与构图是开放范围；02 §4.4 三按钮审批布局是推荐交互，需要记录布局调整。

## 选项

1. 保持原布局，仅调整颜色、圆角和阴影。
2. 重排空白会话、工作台、侧栏与设置，但保留审批所有操作同权平铺。
3. 重排界面阅读顺序，并将审批次级操作集中到具名菜单；主要批准/拒绝保持同一固定决策行。

## 决定

采用 3。空白会话按标题、实际输入框、紧凑任务建议、真实上下文组织；有消息后保持历史视口和底部输入区。输入草稿、附件与键盘语义不改变。左右面板统一 64px 头部基线，元信息与操作分层；设置以档案/实际配置为主体，新增和高级表单按需展开。

审批页脚直接保留“拒绝”“批准”，左侧“更多审批操作”菜单提供“在表格中预览”和“本会话同类操作自动批准”。后者带原有完整说明，仍必须由用户显式选择，提交原有 `approve` 与 `remember=true` 契约；打开菜单、聚焦、查看预览或关闭菜单都不产生决定。不改变权限默认、批准名单匹配规则、安全校验和强制备份。

## 后果与相同验收标准

- 优点：主要决策在窄列及短窗口保持同一行，次级操作不挤掉批准/拒绝；减少重复盒子与技术字段抢占首屏。
- 代价：自动批准比原平铺布局多一步打开菜单。使用具名触发器、完整菜单文案、键盘打开与焦点反馈维持可发现性。
- 继续验证真实审批/拒绝、理由、预览、显式自动批准、忙态防重和服务端记录；区域答案仍绑定确认时修订。保持输入、滚动、主题和减少动效的既有标准。
- 视觉复核按实际页面判断阅读顺序、比例、对齐与密度；类型与构建门禁不能证明美感，也不以骨架屏作为页面完成证据。结果见 [本轮验收](../acceptance/ui-editorial-2026-10-02.md)。
