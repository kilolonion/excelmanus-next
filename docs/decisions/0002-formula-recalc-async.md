# 0002 公式重算改为异步完成，放宽大表增量重算目标

- 状态：已接受
- 日期：2026-09-29

## 背景

07 §12 公式引擎验证项要求"5 万行 × 10 列公式修改一个输入后增量重算 ≤ 500 ms"。M0-A2 实测（`spikes/univer-formula/REPORT.md` §2）：

- 单输入修改重算 p50 7,120 ms / p95 7,248 ms，超标约 14 倍；结果逐格校验正确。
- 耗时与**工作簿中的公式总数**线性相关（≈ 0.13 ms/公式），与受影响单元格数无关。根因是 `@univerjs/engine-formula@1.0.2` 每轮计算都为全部公式重建依赖树，AST 缓存容量固定为 5,000 条（模块常量，不可配置）。
- 重算期间 JS 线程被整段占用：事件循环最长停顿 6.9 s。
- 函数覆盖达标（150/150），中文表名/定义名正确；中文函数名不支持。

负责人决定：不 patch Univer、不切换到 07 §2.2 备选，接受现状并调整目标与流程。

## 选项

### 选项 A：接受，重算异步化并放宽目标（采用）

### 选项 B：`pnpm patch` engine-formula（扩大缓存、依赖树按脏区增量）

- 缺点：每次升级 Univer 都要重做补丁；与"前后端同一精确版本"约束叠加后升级成本高。

### 选项 C：07 §2.2 备选（自有模型 + 自研依赖图）

- 缺点：工作量最大，M1 推迟。

## 决定

选 A，具体改动如下：

1. **提交不等待重算**。修订 07 §3.3：`等待公式增量计算完成，收集写入公式的计算值与错误` 改为：
   - 提交在 mutation 应用后立即得到新 rev，写日志并广播（与现在相同的事务边界）。
   - 重算完成后，文档 actor 把公式结果作为**同一文档的后续修订**提交（来源 `source.kind = "engine"`，写集为结果单元格）。这样"日志是唯一事实源"和"修订号严格递增"都不变。
   - 公式数量低于阈值（初设 5,000，与引擎 AST 缓存容量一致，M1 基准测试后调整）的工作簿，提交路径同步等待重算，行为与原文档一致。
2. **公式引擎不与文档 actor 共用线程**。文档 worker 内的 Univer 实例启用 `UniverSheetsNodeCorePreset({ workerSrc })`，把公式计算放进 rpc-node 子 worker，读取、提交、广播不被重算阻塞。该方案是否可用在 M1 用基准测试验证；不可用时退回"每个含大量公式的文档独占一个文档 worker"。
3. **代理可见的计算状态**。`workbook_edit` 的结果与 `workbook_read` 的公式单元格增加计算状态：`computed` / `pending`（附预计完成的修订提示）。代理需要结果时，可用 `recalculate` op 同步等待（受工具 `timeoutMs` 约束）。工作台对待算单元格显示"计算中"。
4. **目标值修订**。07 §12 公式引擎行的通过标准改为："覆盖 ≥ 95%；公式 ≤ 5,000 的工作簿增量重算 ≤ 500 ms；5 万行 × 10 列场景提交确认 ≤ 50 ms（不含重算）、重算不阻塞读取与广播、重算完成 ≤ 10 s"。07 §1"写入后公式立即有计算值"补一句"大量公式的工作簿为异步完成"。
5. 中文函数名：输入层（工作台公式栏、`workbook_edit`）检测到非英文函数名时返回 `FORMULA_ERROR` 并提示对应英文名，不做本地化函数名翻译。

## 后果

- 正面：大表提交与读取延迟不受公式数量影响；不维护 Univer 补丁；升级 Univer 后若官方改为增量依赖树，可直接受益（升级时重跑 `spikes/univer-formula` 基准）。
- 负面 / 代价：
  - 代理在大表上写入后立即读取，可能读到 `pending` 状态，需要多一次等待；提示词与工具说明要写清楚。
  - 工作台要处理"计算中"状态。
  - 引擎结果修订会让日志多一类记录，要在 11 的契约中登记 `source.kind = "engine"`，并在 10 的投影重建测试中覆盖。
- 需要跟进的事项：
  - M1：验证 rpc-node 公式 worker 方案；测出阈值（公式数 → 重算耗时曲线），确认后把 01 §5.1 相关目标值改为硬性。
  - 修改 07 §1、§3.3、§12，06 `workbook_edit`/`workbook_read` 输出中的计算状态字段，11 修订来源枚举。本 ADR 接受后逐项同步，不允许长期不一致。
  - 附录 C T-2 以本 ADR 关闭。

## 验收标准符合性

- 07 §12 公式引擎：覆盖 150/150（≥ 95%）已满足；性能项按上面修订后的标准在 M1 基准测试中验收。
- 14 中涉及"写入后公式值"的验收场景：结果以引擎修订异步到达，场景断言改为"在重算完成修订到达后值正确"，并新增断言"重算期间读取与广播不被阻塞（事件循环停顿 ≤ 100 ms）"。
- 会话日志/活文档硬性约束（修订严格递增、日志先落库、单一写入者）不变：引擎结果走与其他来源相同的写入路径。
