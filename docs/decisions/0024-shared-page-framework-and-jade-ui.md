# ADR 0024：共享页面框架与玉绿界面

- 日期：2026-10-10
- 状态：采用，浏览器视觉验收待完成
- 来源：用户批准九张主要页面概念图，并明确要求优先真实体验、成熟组件、抽象相似页面框架。

## 背景

原界面的页面标题、分区、列表、详情与空状态分别组合，难以保持视觉和交互一致。用户要求整体重构，而非局部调色。09 张概念图覆盖工作台、首页、文件、团队、审批、模型、技能、首次引导和窄屏；图中示例内容不构成新增功能需求。

## 选项与决定

保留 React 19、Tailwind 4、Zustand、Radix UI、CVA 和 Lucide 包装层，不更换引擎、不增加依赖、不更改许可证门禁。采用白色/冷灰表面、玉绿主操作、琥珀审批、红色错误的统一浅深色 token。

建立两个层次：
1. components/ui/page-layout.tsx 提供 ApplicationFrame、PageHeader、PageSection、ListDetailLayout、PageState、SettingsRow。
2. components/layout 组合业务工作区，ResourceBrowser 统一模型/技能/MCP 的搜索、选择和详情，业务组件继续拥有 API 和操作状态。

工作区页选择进入现有 Zustand 状态，侧栏、首页入口与快捷键使用同一来源。设置分区、错误/加载/空状态经 common 复用。不能为了统一而把规则/记忆的分组编辑强行改成同一种资源详情页。

## 交互变化与原验收语义

- 文件从侧栏中的局部浏览升级为完整列表/详情工作区；原来的上传、打开、重命名、删除、下载、路径校验与确认仍复用。选择文件只展示真实元数据，显式打开才切换文档。
- 团队有独立工作区，复用 TeamPanel 和 ChatPanel，依旧以真实 roster 和代理状态为准。
- 固定审批入口保留；详细修改内容在 Radix 对话框审阅，批准/拒绝仍使用同一 approvalId 与后端接口，不改变授权决策。取消关闭不执行写入。
- 模型、技能、MCP 使用共享列表详情。搜索不销毁正在编辑的详情。窄屏先列表后详情，返回列表仍保留编辑器。
- 设置关闭、分区切换、资源切换前检查未保存内容；保存失败不清除保护。显式取消模型/MCP 编辑也经过检查。
- 小屏侧栏使用 Radix 模态抽屉；表格/对话继续沿用原标签切换，不新增远程连接或手机专属产品能力。
- 首次引导复用真实设置入口，避免维护另一套凭据表单；提示云模型会向已配置提供商发送相关内容。

同一验收标准仍是 02 的关键操作可达、04 的审批语义、07 的写入和备份约束、11 的真实接口以及 14 的真实边界。此决定只调整前端呈现与导航，不扩大后端能力。

## 后果与限制

统一样式和结构减少重复页面；业务动作与基础布局解耦。文件与设置详情仍有各自合法信息密度，不能机械复制图片中的虚构字段、数字和按钮。

编码执行环境独立 Chromium 创建进程 socket 被拒绝；已有云浏览器可访问公网，正准备独立预览环境。类型、静态渲染、构建、服务边界测试不能代替真实浏览器的键盘焦点、滚动、深浅色对比和响应式验收；这些必须明确记录为未验证，不将概念图当成产品截图。
