# 0007 将 Stitch 草案接入为页面设计参考

- 状态：已接受
- 日期：2026-09-30

## 背景

后续补入的 `stitch/` 含视觉规范、工作台和设置中心 HTML/截图，尚未纳入唯一实现依据 `docs/`。负责人要求整理进文档，并明确「这是参考草案，不需要一比一复刻，以实际功能出发考虑最终的页面设计」。原草案包含与现有范围、权限、修订和快捷键不一致的示例，不能原样作为规格使用。

## 选项

### A：将原 HTML 与视觉参数作为最终页面规格

能快速获得相近外观，但会把示例按钮与状态固化为需求，引入未定义的终端/分享/成员入口、虚假的成功反馈与远程素材，并挤压不同阶段的实际功能。不符合负责人要求。

### B：提炼视觉参考，逐项映射现有功能和验收

保留可用的构图、排版、卡片和状态表达，把冲突内容改写或排除；文档内存档截图并明确其参考身份。需要一次整理和交叉链接，最终页面可按真实任务调整。

### C：只在文档里链接 `stitch/`

改动少，但实现者仍需在依据目录之外推断需求，无法区分草案与正式约定，后续环节容易照抄未经确认的功能。

## 决定

选择 B，新增 [16 页面设计参考](../16-design-reference.md)，在交互、模型、桌面、质量与里程碑章节接入入口，保留工作台与设置截图到 `docs/design/reference/`。

- 配色、字体、尺寸与构图保持【开放】，不把参考升级为一比一复刻承诺；同一开放范围内的视觉调整无需额外 ADR。
- 最终页面从已定义功能、用户任务与真实状态出发；产品范围和硬性安全、数据、日志、契约约束不变。
- 02 的现有【推荐】交互继续适用；本决定不推翻窄屏标签切换、快捷键、权限范围或备份机制。
- 截图的型号、延迟、配额、备份与修订数字是示例；终端、分享、成员等不因此成为需求。
- 未定义的配置导出进入附录 C P-11；不新增接口、依赖、素材许可例外或验收完成标记。

## 后果

- 正面：各阶段可以在 `docs/` 内找到对应参考、正式行为依据和差异解释；实现可按真实内容重排页面。
- 代价：存档截图仍含已排除的示例，阅读时需同时查看 16 §5；最终页面不会与草案完全一致。
- 跟进：实现阶段按既有真实边界验收留证据；若需要新的产品能力，先补需求与契约或记录待决问题。

## 验收标准符合性

14 的场景 1、2、4–6、8–14、18–23、25 仍检查实际操作和可信状态。16 §6 把视觉复核附着到对应场景，不增加像素匹配门禁，测试策略继续遵循 ADR 0006。文档接入核对来源、差异、链接、截图完整性；不将这些检查当成产品运行验收。

## 2026-09-30 补充：手机初步草稿

同一接入方式适用于后补 `stitch_/`：视觉规范与桌面原稿相同，手机表格/对话两页整理至 [16 §7](../16-design-reference.md#7-手机页面参考p2)，截图逐字节存档。继续保留 P2 范围与开放构图，不新增提前实现、像素复刻或草案能力承诺；语音与逐项批次处理列入附录 C P-12/P-13。手机配对、只读浏览和真实同步要求沿用 13 §5，文档检查不替代实机验收。
