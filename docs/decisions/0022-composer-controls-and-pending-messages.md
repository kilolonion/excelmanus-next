# ADR 0022：组合模型入口与待处理消息

- 日期：2026-10-02
- 状态：已采用（用户提供四张交互参考并明确要求）

## 背景

用户要求模型与思考等级采用组合入口、大圆角列表和离散滑条，发送/暂停使用蓝色圆形图标键；运行中发送遵循已设定的默认行为，不拆成策略按钮。引导/排队消息需要明显的待送达反馈、点击编辑、打断发送和删除。现有运行时支持三策略，但设置未暴露默认值，前端硬编码 steer，只能撤回到草稿。

## 选项

1. 只更换控件外观，保留策略分拆按钮。
2. 浏览器先撤回旧消息，再提交新消息。
3. 默认行为由服务端设置决定，气泡操作使用同一发送接口的原子替换契约。

## 决定

采用选项 3，满足用户明确的输入区与气泡操作要求。更新 02 §3.2–3.3、04 §4 与 11 消息接口。模型组合菜单只列实际配置档案；思考等级仍保存当前档案，与设置中心一致。六个滑条停点对应现有无/低/中/高/极高/最高；默认通过重置选择，历史 minimal 只读回显示。菜单和滑条复用 Radix 控件，支持键盘；不因图片中的麦克风新增语音能力。

AppSettings 增加 defaultDispatchMode，默认 steer。省略 mode 的普通发送在服务端读取设置；显式 mode 继续用于气泡的 interrupt 与编辑时保持原策略。发送按钮有草稿显示上箭头，运行中无草稿显示暂停方块，暂停保持已有队列语义。

未生效消息显示虚线浅色气泡和灰色时钟；用户随后要求移除下方整行紫色提示，待送达状态改为辅助技术描述；HTTP 已受理与模型已看到是两个不同阶段。点击气泡就地编辑，保留图片和区域引用；打断可发送编辑后的正文。编辑/打断用新的 clientMessageId 与 replacesDispatchId，在一笔日志事务中撤回旧派发并登记新派发。不改写历史；删除只追加 cancelled，聊天隐藏撤回消息。替换仍校验附件与选区，最后一次异步校验后重新检查旧派发状态，已生效/撤回返回冲突。幂等重复返回已有派发，不重新撤回或再次发送。

## 后果与验收

- pending 不能伪装成网络发送失败；请求失败保留草稿，操作失败保留可重试气泡并提示。
- 编辑后以新消息位置显示，服务端维持实际接收顺序；旧内容保留在日志用于重建。
- 不重复携带当前输入框附件或选区，替换只复用旧消息自己的引用。
- 真实 HTTP/WS/SQLite 测试验证默认策略、替换、幂等、已生效冲突、旧消息不进入模型和投影重建；真实浏览器验证菜单、滑条、键盘、暂停、编辑、删除、打断、刷新和窄屏。证据见 [专项验收](../acceptance/composer-pending-2026-10-02.md)。
