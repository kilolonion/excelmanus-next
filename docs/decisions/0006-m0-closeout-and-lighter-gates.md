# 0006 M0 收口：剩余验证项顺延，门禁与测试降为关键路径

- 状态：已接受
- 日期：2026-09-29

## 背景

负责人决定：项目当前不是工业级交付，优先尽快推进产品代码。M0 已完成 Univer 模型（0003）、公式引擎（0002）、QuickJS 沙箱（0001）、node:sqlite（0004）、AI SDK 单步（0005）。剩余项（xlsx 保真语料、库对比、对象层、截图渲染、并发模糊、大文件分块、同步通道原型、ChatGPT 订阅）若按 07 §12、14 §2 的原判据全部做完，会显著推迟 M1。

## 决定

1. **M0 剩余项顺延**到首次需要它的里程碑，在该里程碑内边实现边验证，不再单独做 spike：
   - 同步通道原型 → 直接在 `packages/server` 实现（复用 `spikes/sync-channel` 代码）。
   - xlsx 编解码 → M1 只做只读导入（xlsx → Univer 快照）；保真写回、语料库、库对比、对象层 → M2。
   - 截图渲染、并发模糊、大文件分块 → M2；ChatGPT 订阅 → M5。
2. **测试降级**（覆盖 14 §2–§4 与 11 §5 的相关硬性条款，直到负责人恢复）：
   - 保留：`pnpm check`（typecheck、lint、依赖方向、许可证）；每个主要能力一条走真实边界的集成测试（真实 HTTP/WebSocket/SQLite 文件 + 假模型）；投影重建测试（便宜且守护红线 3）。
   - 取消：每个 REST 端点逐一契约测试、覆盖率要求、状态机逐转换单测、`criteria.json` 式的逐项判据、里程碑验收记录中的逐场景证据要求（改为简要记录已手动/自动跑过什么）。
   - 不写纯粹重复实现的单测；纯逻辑只在容易出错处（区域运算、reduce、冲突判定）测。
3. **查询层**：不引入 Kysely，直接用 `node:sqlite` 的预编译语句 + 手写迁移（推翻 03 §10【推荐】的 Kysely）。理由：同步 API、表少，少一层适配。
4. 不变：AGENTS.md 的全部硬性红线（日志事实源、同一事务、先写 intent、安全、许可证、依赖方向等）。

## 后果

- 正面：M1 可以立即开始，spike 结论直接用于产品代码。
- 负面：保真、并发、渲染的风险推迟暴露；回归主要靠集成测试与手动验证。
- 跟进：M2 开始时重新评估 xlsx 保真是否需要恢复语料测试；附录 C 中 T-1、T-3、T-6、T-9、T-10、T-13 保持打开。

## 验收标准符合性

里程碑退出条件改为：对应验收场景可在本机手动或用假模型集成测试跑通，并在 `docs/acceptance/<里程碑>.md` 简要记录。
