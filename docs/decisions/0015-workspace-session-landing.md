# ADR 0015：工作区绑定会话与可复用的空白落点

- 日期：2026-10-01
- 状态：采纳（M6 前端续修）

## 背景

01 §3.4 已要求每条会话绑定工作区并提供数据目录下的默认工作区。现有后端启动登记默认目录，创建会话通过 `session.created.workspaceId` 持久化，运行时从会话投影关联工作区获取文件根目录，因此真实绑定和默认回退已经存在。前端虽按区筛选列表，但只加载全局前 50 条；刷新打开全局最近会话，删除后可跳到其他区，单工作区入口无法添加文件夹，自动落点不能跨客户端复用。

用户明确要求参照第一代桌面行为，并提供侧栏截图。本次仅核对其导航行为（首选工作区、真实空白会话、自动复用与显式新建），将需求先写入新版 docs；没有复制旧仓库代码。实现仍由新版协议、日志与同步通道独立完成。

## 选项

1. 保持每次自动落点都创建会话：实现少，但刷新/多窗口容易产生空白条目，工作区选择丢失。
2. 未发送前只存本地临时对话：不能满足用户要求的真实持久会话落点，也需单独处理模型、权限与附件归属。
3. 后端真实绑定 + 自动空白复用 + 显式新建 + 本地导航偏好：无需新的会话状态来源，也能保留现有会话草稿及日志订阅。

## 决定

采用选项 3，具体流程以 02 §2.3 与 11 §4.1 为准。

- `reuseBlank` 仅用于自动落点；服务端基于现有日志和投影判断，不增加不可重建的 blank 状态列。
- 复用不改写日志、模型、权限或系统提示词。正常新建仍经日志事务创建投影，提交后推送事件。
- 前端记录各工作区最后选择的会话 ID，先恢复有效选择，再用同区最近会话或自动空白落点；删除不跳区。
- 加载完整会话分页，提供按工作区过滤的协议查询；聊天页同时显示各工作区及其子会话，标题搜索按这些可见分组进行，文件页保持同区语义。
- 导航请求序号防止旧返回抢占新选择；文件列表另有请求序号及工作区校验；跨区清除文档与选区上下文。
- 侧栏与设置共用登记对话框，桌面调用既有 `chooseDirectory` 桥，本机 Web 输入绝对路径；不扩展路径权限或跨区迁移。

用户随后明确指定截图中的“项目 → 聊天”层级。本次将原先单工作区筛选的聊天页调整为工作区分组列表，折叠只影响展示；最近 5 条与展开更多控制列表长度，选中的历史始终可见。分组可在指定工作区显式新建，并可进入该区文件页；真实绑定、默认落点、删除不跳区与刷新恢复保持同一组验收标准。搜索只在既有已授权列表的标题中匹配，不扩展到文件内容或聊天全文。

## 后果与验收

首选工作区是本机导航偏好，默认工作区仍由后端注册信息决定。明确新建可以保留多条空白会话，这是用户动作的结果；自动落点复用仅接受尚未发生任何后续记录的会话。历史默认权限与冻结提示词不会被当前设置覆盖。

沿用 14 的真实边界标准：HTTP 创建与复用、并发落点、WS 创建事件、真实 SQLite 重启及投影重建、跨区文件隔离、超过 50 条分页、浏览器刷新/切换/删除后的落点、登记成功与失败。证据见 [工作区与会话续修验收](../acceptance/workspace-session-landing.md)。不据此宣称 M6 或文件管理全部完成。
