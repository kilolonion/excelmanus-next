# 多文件批量交付

目标是每个输入都有明确结果，转换一致且失败可追踪。批量方法可以是顺序处理、批量脚本或代理分工；文件数量本身不决定是否需要团队。

## 范围与一致性

- 用 `find` 确定目标清单，排除历史输出、临时文件和明显重复副本，记录输入相对路径。用户的目录/文件范围优先，不因搜索命中就扩大任务。
- 选有代表性的文件检查表头、工作表结构、单位与公式。结构相同的文件可共用转换；异构文件先分组，不让一个样本决定全部映射。
- 明确输出命名、目标目录和覆盖规则，避免不同目录的同名输入映射到同一输出。维护“输入—规则组—输出—状态—核验—失败原因”清单。

## 执行路线

- 改动简单或文件间有依赖时，顺序处理便于核验。
- 同构且计算密集时，可用 `run_script` 批量处理；分组大小按数据规模与执行预算选择，发布行为以工具说明为准，不承诺跨文件事务。
- 可独立读取/判断的文件组可以分给子代理。若 `agent_spawn` 可用，为每组给出输入、输出、转换口径、验收条件和失败处理；具体角色、租约与队列行为由工具说明提供。没有派生工具时使用顺序或脚本路线。
- 跨文件汇总与对账先统一口径再计算，避免把共享输出交给多个执行者同时写。委派的是处理工作，汇总者仍负责最终核验。

## 收口与重试

收集每个输入的结果；需要时用 `agent_status` 查看报告。代理结束、脚本完成或输出文件存在不等于数据核验通过。比较处理前后行数、关键合计和规定的结构，对失败文件保留具体原因。

重试前读取清单与实际输出，只处理未完成项或明确需要重算的项，避免在已处理结果上再次执行非幂等转换。中断时交付已完成、失败、未处理三类状态。

需要设计命名与分工清单时，读取 [批量实例](references/examples.md)。
