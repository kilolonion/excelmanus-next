# 数据核对与对账

目标是给出可定位、可解释的差异，而非仅判断两张表是否相等。

## 匹配决策

- 先确定两边的数据粒度、期间、单位和匹配字段。行顺序不同不代表业务差异；只有用户要求版式逐格比对时才按位置比较。
- 检查匹配键的唯一性、空值和格式。编码的前导零与大小写可能有业务意义；只做有依据的规范化。保留原始键便于追溯。
- 同键多行时先判断是否是一对多业务关系。根据目标按键汇总，或增加稳定的明细键；不能直接连接产生笛卡尔乘积，再把虚增金额当差异。
- 容差和舍入规则按用户口径。没有口径时展示原始差额与精度问题，必要时询问；不默认为所有币种与数量采用 0.01。空值与零分别比较。

## 常见路线

用 `workbook_read` 观察来源，用 `workbook_analyze` 的差异比较或 SQL 分组匹配；复杂关系可用批量脚本。把差异分成仅 A 有、仅 B 有、两边都有但字段不同、无法确定匹配四类。通过 `workbook_edit` 输出独立报告；用户明确指定其他输出方式时遵从。

每条报告保留来源文件/工作表与行位置、业务键、两边原值、差额及差异类别。无法匹配的记录不能隐藏在“匹配成功”统计里。

## 核验与交付

核对两边输入条数、唯一键数、重复/空键数及每类结果数。按金额核验：两边金额差应能由缺失记录与匹配记录差额解释，避免只核验行数。原始来源默认不改动。

交付给出匹配口径、分类数量、金额差和报告位置；报告存在未决匹配时说明其影响。

处理一对多或重复键时，读取 [匹配实例](references/examples.md)。
