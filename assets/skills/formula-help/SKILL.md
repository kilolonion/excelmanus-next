# 公式设计、解释与排错

先确认用户需要解释、生成还是修复公式；解释已有公式通常只需读取，不应顺便改写。

## 设计判断

- 读取公式、引用区域及其数据含义，区分公式文本、显示文本和计算值。业务字段相同不保证类型相同，查找失败需检查文本/数字、空格和重复键。
- 根据目标软件和版本选函数。兼容旧版 Excel/WPS 时不能仅因新函数更短就使用它；已有模板的函数习惯和用户要求优先。
- 确定相对/绝对引用，以及复制到其他行列后的含义。数据会增长时考虑表对象或可维护范围；整列引用的性能代价与新增行遗漏的风险分别评估。
- 百分比、均价、增长率明确分母。除数为零、空值、未匹配与真实 0 分开；不能用 IFERROR 把所有错误静默变成 0。

## 解释与修复路线

`workbook_read` 可读取公式及关联数据，`workbook_analyze` 可校验公式错误，`workbook_edit` 用于用户要求的写入。调用格式以工具说明为准。

解释时从结果含义到各部分计算，再说明引用对应的业务字段。修复时先找根因：被删除的引用、错误类型、缺失键或不支持函数；引用链过长时聚焦实际影响的上游范围。

可以先在一个代表性单元格验证，再填充；已有正确公式时优先沿用其结构。公式解释任务直接给说明，不启动完整写入流程。

## 结果检查

写入后核验首行、末行、空值、零值与未匹配情况。计算缓存缺失或引擎不支持函数时，报告“已写入但未验证计算结果”，不能把空缓存当成 0。交付说明公式位置、适用范围和验证边界。

需要处理填充引用或错误掩盖时，读取 [公式实例](references/examples.md)。
